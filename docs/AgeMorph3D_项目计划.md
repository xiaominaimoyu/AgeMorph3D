## 一、项目定位

**一句话目标**：用户面对摄像头或上传一张照片，系统检测人脸并重建为参数化三维头模；拖动年龄滑块（20—70 岁），在浏览器中实时预览不同年龄的三维形象，并可导出 glTF 模型与效果图。

**必须守住的三条边界**（写进开题报告与论文，避免答辩时被追问）：

1. **做"年龄变换"，不做"年龄预测"**。系统输出的是统计上合理的年龄方向形变，不是对某个人未来长相的预言。评价指标围绕"目标年龄符合度 + 身份保持"设计。
2. **适用范围 20—70 岁**。BFM/FLAME 主要由成年人扫描数据训练，儿童头型（颅骨比例、面部占比）不在模型表达范围内。儿童相关内容只出现在论文"局限与展望"。
3. **全部本地处理**。人脸数据不出本机，不上传云端；这是合规要求，也是系统卖点。

**三个模块的难度与主备路线**：

| 模块 | 保底路线（必须完成） | 主线路线（争取完成） | 难度 |
|---|---|---|---|
| M1 人脸检测与对齐 | YOLO26n-face（yolo-face 权重）+ WIDER FACE 微调 | — | 低 |
| M2 单图三维重建 | 3DDFA_V2 + BFM（CPU 实时，自带处理好的模型与 demo） | MICA + FLAME 全头 | 中 |
| M3 跨年龄变换与可视化 | BFM 2009 `04_attributes.mat` 年龄方向 → 逐顶点位移 → three.js morph target | 自估计 FLAME 空间年龄方向 + SAM 纹理老化 | 高 |

## 三、系统架构

### 3.1 技术架构

```
┌─────────────────────────── 浏览器（前端 / 学生 B）───────────────────────────┐
│  UI：摄像头 / 上传 → 拍照 → 年龄滑块（20—70）→ 导出                         │
│  three.js：模板网格 + 形状基 + morph target + UV 纹理 + 光照                 │
└───────────────▲───────────────────────────────┬────────────────────────────┘
                │ WebSocket：每帧仅传 ~40 个浮点    │ HTTP：上传照片 / 请求老化 / 导出 glTF
┌───────────────┴───────────────────────────────▼────────────────────────────┐
│ 后端（Python / FastAPI / 学生 B 搭骨架，A 提供推理实现）                     │
│  M1 检测：YOLO26n-face（ONNX）                                               │
│  M2 重建：3DDFA_V2（保底）/ MICA（主线）→ β, ψ, pose, UV 纹理                │
│  M3 变换：β' = β + w(age)·Δβ_age；SAM 生成目标年龄纹理                      │
│  导出：glTF（含 morph target）/ 效果图                                       │
└──────────────────────────────────────────────────────────────────────────────┘
        GPU 侧（离线）：SAM、批量重建回归、模型微调——与实时链路隔离
```

### 3.2 两条时间线（必须分离）

- **实时线**：检测 → 裁剪对齐 → 3DMM 回归 → 姿态驱动渲染，逐帧执行，目标 ≥ 30 FPS。
- **离线线**："拍照 → 生成 → 查看"：年龄方向计算、SAM 纹理生成、glTF 导出，一次性执行，可等待数秒。

### 3.3 关键工程约束

1. **顶点拓扑一致性**。年龄方向的逐顶点位移必须与前端加载的模板网格顶点编号一一对应。保底方案下 BFM 顶点顺序要与导出网格对齐；主线方案切到 FLAME（5023 顶点）时，morph target 与 UV 全部按 FLAME 拓扑重做。**这是 M3 的第一优先级技术风险，第 17 周前必须验证。**
2. **年龄方向归一化**。`Δβ_age` 以"每岁一个单位向量"还是"视觉强度归一化向量"需在原型阶段定死，否则滑块 0—1 的映射在 20—70 岁之间会非线性跳变。建议对 Δβ_age 做 L2 归一化，滑块 w ∈ [0, 1] 均匀映射。
3. **模型许可与资产**。FLAME 需官网注册，BFM 2009 需申请；GNM Head（Google 2026 年发布，Apache-2.0）作为免申请备选。所有模型文件、数据集不入 Git（`.gitignore`），仓库只记录获取方式。
4. **ONNX 化**。检测与重建模型导出 ONNX，后端用 onnxruntime 推理，避免每帧 Python/PyTorch 开销，也便于 B 在不装 CUDA 的机器上调试。

## 四、前后端接口约定（第 1 阶段冻结，第 2 阶段后只增不改）

### 4.1 WebSocket（实时）

| 方向 | 消息 | 内容 |
|---|---|---|
| 前端 → 后端 | `frame` | 摄像头帧（JPEG/WebP，可降采样）或 `{"mode":"params","beta":[...],"psi":[...]}` 复用 |
| 后端 → 前端 | `face_state` | `{bbox:[x,y,w,h], landmarks:[[u,v]×5], beta:[50], psi:[50], pose:{R:[9],t:[3]}, ts}` |
| 后端 → 前端 | `error` | `{code, msg}`（无人脸、多人脸、超时） |

约束：单条 `face_state` 序列化后 < 1 KB；后端不做网格回传。

### 4.2 HTTP（离线）

| 方法 | 路径 | 用途 | 返回 |
|---|---|---|---|
| POST | `/api/reconstruct` | 上传照片，返回重建参数与 UV 纹理（base64 或静态文件 URL） | `{beta, psi, pose, texture_url, mesh_id}` |
| POST | `/api/aging` | `{mesh_id, age}` → 目标年龄形状参数与纹理 | `{beta_aged, texture_url}` |
| GET | `/api/assets/{mesh_id}` | 模板网格、形状基、morph target 定义 | glTF/GLB + JSON |
| POST | `/api/export/gltf` | 导出当前年龄的模型 | 文件流 |
| POST | `/api/export/image` | 导出渲染截图 | PNG |
| GET | `/api/health` | 模型加载状态、版本、推理设备 | `{models:[...], device}` |

### 4.3 morph target 导出格式

```json
{
  "mesh_id": "flame_v1",
  "age_range": [20, 70],
  "targets": [
    {"name": "age_20", "delta": "age_20.bin"},
    {"name": "age_70", "delta": "age_70.bin"}
  ],
  "slider": {"weight": 0.0, "direction": "linear"}
}
```

`delta` 为 float32 逐顶点位移数组（顶点数 × 3），以二进制文件提供，避免 JSON 膨胀。三档以上（20/35/50/70）时前端做分区间插值。

## 八、评价实验设计（阶段 4 执行）

1. **检测**：WIDER FACE 三个难度子集 mAP + FPS；对比微调前后与 YOLO5Face / FaceBoxes 基线。
2. **重建**：AFLW2000-3D NME；与 3DDFA_V2 原始权重、MICA 对比。
3. **年龄变换（核心）**：
   - 目标年龄符合度：MiVOLO 对生成图像估计年龄，统计 |估计年龄 − 目标年龄| 的 MAE，绘制 20—70 岁曲线。
   - 身份保持：ArcFace 计算原图与生成图的余弦相似度，对比"仅 2D 老化（SAM 直接输出）"与"本系统 3D 老化"。
   - 定性对比：FG-NET 同一人不同年龄真实照片与系统生成结果并排。
   - 消融：仅形状老化 / 仅纹理老化 / 形状+纹理。
4. **系统**：端到端延迟、渲染帧率、payload 体积、Chrome/Edge 兼容性矩阵。
5. **主观**：10—20 人，5 分制双维度（像不像目标年龄 / 像不像本人），报告均值与标准差。

所有图表自行绘制（任务书明确禁止贴图），实验原始数据与脚本入 `experiments/`。
