## 1. 运行与输入

从项目根运行，使用现有后端环境，无新增依赖：

```powershell
& 'backend/.venv/Scripts/python.exe' -m preprocessing.duplicate_screening --help
```

实现见 [duplicate_screening.py](../preprocessing/duplicate_screening.py)，回归见 [test_duplicate_screening.py](../backend/tests/test_duplicate_screening.py)。输入承接 [D06/P01 归档准备](归档解压与逐图核验开发记录.md)，读取方向已校正、未经过 [P02 裁剪缩放](框与关键点坐标转换开发记录.md)的标准化 PNG。裁剪可能抹去图像差别，因此本批不拿对齐后的局部图代替原有准备输入。

计划 schema 为 `agemorph3d-duplicate-screening-v1`，字段必须完整且无额外项：

| 字段 | 要求 |
|---|---|
| `schema_id` / `plan_id` | 上述 schema 和稳定计划标识 |
| `preparation_report` / `prepared_manifest` | D06 报告及其 K5 副本的相对路径、准确 bytes、SHA-256 |
| `fingerprint_contract` | `fingerprint_contract()` 返回的既有算法、限制与运行环境完整副本；不允许调整阈值或以 bool 替代数字 |
| `algorithm_sources` | 恰好绑定 `tools/near_duplicate_probe.py` 和 `tools/evaluation_readiness_probe.py` 的路径/bytes/SHA-256；还须与实际运行源码一致 |
| `reserve_bytes` | 0 至 64 GiB 的整数预留；另计最多 4 MiB 报告空间 |

原 K5 清单也按准备报告中的 pin 加载。原清单与准备副本仅允许既有 manifest_id 和已记录的预处理接触差别；全记录数量、顺序、年龄精度/区间/null、用途、数据集命名空间、subject/linked_subject、派生链和历史 processing 均保持。输入最多 32 图；完整对数为 `N*(N-1)/2`，32 图的 496 对已实际回归。

本机保存的合成例可这样执行；它依赖被忽略的本机证据，克隆源码不会自带这些文件。输出必须使用新版本目录：

```powershell
$p03Plan = 'output/research/duplicate-screening-20261029/probe-v1/positive-plan.json'
$p03Sha = (Get-FileHash -LiteralPath $p03Plan -Algorithm SHA256).Hash.ToLowerInvariant()
& 'backend/.venv/Scripts/python.exe' -m preprocessing.duplicate_screening `
  --root . --plan $p03Plan --plan-sha256 $p03Sha `
  --output-dir 'output/research/duplicate-screening-20261029/manual-example-v2'
```

不要把修改后的算法、准备报告或 K5 副本接到旧计划下，也不要覆盖已保存证据。准备报告状态允许 passed 或 failed，但要求其输入稳定；失败图仍属于本批请求。

## 2. 复用算法与证据含义

直接调用既有 [near_duplicate_probe.py](../tools/near_duplicate_probe.py) 的 `_decode`、`_matches` 和 `_components`，不重写另一套 dHash 或运行 N0 专用 `build_report`。旧研究工具要求 N0 及精确研究年龄，本适配器独立接 K5，不伪造年龄或 N0 身份，也不读取旧研究图片、保留组模型结果或权重。新 schema 与旧 `agemorph3d-near-duplicate-v1` 算法标识分别记录，不宣称重做旧研究。

既有算法固定 Python 3.11.16、Pillow 13.0.0；同时记录实际 JPEG/zlib/WebP codec 版本。每图沿用原视图及水平镜像，将 RGB 转灰度，LANCZOS 缩至横向 9×8 / 纵向 8×9；右大于左、下大于上按行产生 64 位 dHash。四种视图组合中，横/纵 Hamming 均不超过 8 才是感知候选；保留全部命中视图。32×32 灰度 MAD/255 仅作诊断，不再按它筛选候选；阈值是已有检索启发值，不是同人或质量通过线。

| 输出证据 | 能说明的内容 | 仍不能说明的内容 |
|---|---|---|
| `normalized_file_sha256` 组 | 本批读到并复核的标准化 PNG 字节相同 | 原始编码文件字节相同；原始文件本批没有重读 |
| `rgb_pixel_sha256` 组及视图成员 | 带尺寸及 RGB 域分隔的像素哈希相同；保留 original/mirror 对应 | RGB 指纹不含 alpha，不等于完整 RGBA 一致，更不等于人物身份 |
| `matched_view_pairs` | 当前固定阈值下的近重复候选及每视图距离 | 并非已接受的重复，更不能把未命中解释为异人或无泄漏 |
| `components` | 候选边的待审查连通分量 | 不推定分量内全部两两相同或共同真实身份 |
| `metadata_audit` | 原 K5 按声明的身份/关联/派生和跨用途问题 | 不代替实际图片或跨源身份核验，不把 review 状态自动改为 recorded |

本批黑白纯色反例中，四个视图全部 dHash 命中，灰度 MAD/255 都为 1；它仍是候选而不是精确重复。不同透明度的同 RGB 图也会共享 RGB 指纹，文件哈希仍有区别。两种情况均有回归，以防把检索工具包装成质量结论。

候选记录原样本 ID、完整行索引、用途和待审状态；`cross_assigned_uses` 仅对除 unassigned 之外存在多种用途时为真。局部 subject 仅在同一 dataset 命名空间且两边已声明时比较；跨数据集相同文本 ID 或任一缺失均保留 null。显式 linked_subject 单独比较，不自动补身份、合并候选或迁移用途。

## 3. 失败、变更与报告

输入 JSON/计划哈希、算法契约/环境/运行源码、K5 语义、报告记录顺序及输出范围在创建目录前检查。JSON/报告有界，重复 JSON key、外部路径、符号链接/reparse 和覆盖旧目录均拒绝。输出只允许新的 `output/research/` 后代。

已准备失败的图直接保留原错误码，不读该图。PNG 超过既有指纹算法的 10 MiB 上限时保留逐图失败并不读取；解码最多 16,000,000 像素，只接受单帧 RGB/RGBA PNG，实际尺寸/模式须符合准备记录且不含待应用 EXIF 方向。坏 pin、坏图或不符的栅格均逐图失败，后续图继续。

全部图和全部请求对进入账本；失败图关联的对记为 uncomparable，不从请求分母删除。报告在比较完成后重查已尝试的 PNG 以及计划、两份 K5、准备报告和算法源码 pin。若成功图此时变化，撤下该图的全部候选边及精确组，保留失败行，相关对改为不可比较；候选 ID 可能有空号，不能把 ID 当列表位置。其他输入变化使整批 inputs_stable/status 失败，已算数值只作诊断。

输出仅一个 `report.json`，包含完整 K5 行、逐图 pin 检查、全部 pair_ledger、候选/精确组/连通分量和原 metadata_audit。不写照片、缩略图、重分组清单或审核后 manifest。退出码：0 为本批所有图片完成指纹且输入稳定，1 为逐图失败或末检不稳定，2 为输入/输出契约拒绝；0 不代表候选已经人工核完。

`candidate_review_complete/cross_source_identity_proven/no_leakage_accepted` 和正式数据、训练、独立评价、服务、生产、G3 标志始终为 false。原历史 NO_FACE 与本批可解码/指纹成功分别记录；不抹去历史失败。
