## 1. 从完整准备清单建立输入包

实现为 [split_freeze.py](../preprocessing/split_freeze.py)，回归为 [test_split_freeze.py](../backend/tests/test_split_freeze.py)。复用 [K5元信息契约](年龄数据清单与用途泄漏审计.md)及 [P03准备清单筛查](准备清单重复候选筛查开发记录.md)，不增加依赖，不启动服务、提取新特征或随机分组。

```powershell
& 'backend/.venv/Scripts/python.exe' -m preprocessing.split_freeze --help
```

计划 schema 是 `agemorph3d-split-freeze-precheck-v1`，字段完整且不接受额外开关：

| 字段 | 契约 |
|---|---|
| `schema_id` / `plan_id` | 上述 schema 与稳定计划 ID |
| `prepared_manifest` | P03 使用的完整 K5 副本 pin：相对 path、准确 bytes、SHA-256 |
| `screening_report` | 固定版本的完整 P03 报告 pin |
| `basis` | 下述分组/候选审查声明包的 JSON pin |
| `assignments` | 原 K5 顺序的全记录 `{sample_id, group_id, use}`，不得漏行、交换或重复 |
| `reserve_bytes` | 0—64 GiB 整数预留；另计两份最多各4 MiB输出 |

`assignments` 仅记录提交者明确提供的声明，不生成分组。每个 use 必须是既有 K5 枚举；与输入 K5 不同的用途会被报告为阻断项，原值保持。不得用本工具把旧研究用途迁移为未见测试。

本机实际保存的合成正例可按以下方式执行；它依赖本机忽略目录中的证据，不会随源码克隆提供，输出须使用新目录：

```powershell
$p04Plan = 'output/research/split-freeze-20261029/probe-v1/positive-plan.json'
$p04Sha = (Get-FileHash -LiteralPath $p04Plan -Algorithm SHA256).Hash.ToLowerInvariant()
& 'backend/.venv/Scripts/python.exe' -m preprocessing.split_freeze `
  --root . --plan $p04Plan --plan-sha256 $p04Sha `

```

## 2. 显式分组依据与候选审查

依据包 schema 为 `agemorph3d-split-basis-v1`，含 `schema_id/basis_id/groups/candidate_reviews`。每个 group 必须有 `group_id/sample_ids/origin/recorded_by/evidence`；所有样本恰好出现一次，成员与 assignments 完全对应。每条候选审查必须有 `candidate_id/sample_ids/decision/origin/recorded_by/evidence`，与 P03 候选顺序、ID和两端绑定，不重新编号；P03末检后的候选 ID 可以有空号。

| 字段 | 值与解释 |
|---|---|
| `origin` | official、human、synthetic、ai、unknown；是来源自述，不是认证结果 |
| `recorded_by` | 可追溯记录者的 ASCII ID，或 null；不自动使用 AI 名称充当真人 |
| `evidence` | 本地 JSON/Markdown 支撑记录的 pin，或 null；只验证准确字节/哈希，不判断正文是否属实 |
| `decision` | pending、uncertain、same_content、different_content；后两者谈的是图像重复关系，不声明人物同一或不同 |

分组或确定审查若缺记录者/支撑 pin，或仅来自 ai/unknown，继续阻断。synthetic 仅供合成契约样例；human/official 也只是带支撑指纹的自述，不能把字段填满解释为真实人工已签认。报告和冻结包始终带 `provenance_assessment=self_reported_declarations_only`、`human_review_verified=false`。

所有候选都要保留审查行，pending/uncertain 均阻断；不能通过删掉困难候选获得通过。`same_content` 要求两端保持同一显式组；`different_content` 不能推翻已保存的标准化文件字节相同证据。不同 alpha 的同 RGB 图、镜像像素相同与真实身份仍是独立问题，沿用 P03 的范围说明。

## 3. 只读核对与阻断出口

P04只打开有界元信息，拒绝以图片、权重或数组作为支撑文件。计划最多512 KiB，其他单件最多4 MiB，最多64份不冲突的 pin、累计最多32 MiB；输出限新的 `output/research/` 后代，拒绝覆盖和链接/reparse 路径。

预检核对 P03 wrapper/算法版本、闭合资格标志及六个输入角色，复用 P03 的原始/准备 K5 谱系核对；准备报告、原 K5、准备副本和算法源码均绑定。P03 的逐图行须与当前 K5 完全相同，逐对账本覆盖全部 `N*(N-1)/2` 请求。根据**保存的**双方向 dHash/RGB哈希复核四视图候选、距离、精确组及连通分量，拒绝漏候选、漏匹配、篡改计数或重写结构；灰度 MAD 仅核有限范围，不重算图像数值。

这不是重新读取原照片或标准化 PNG：P03 图片 pin、特征及解码状态仍是保存观察，`image_pins_rechecked=false`。候选无命中仍不证明异人或没有泄漏；来源自述和内容哈希不构成法律许可。

| 主要阻断码 | 保留的实际问题 |
|---|---|
| `SCREENING_INCOMPLETE_OR_UNSTABLE` | P03仍有失败或输入不稳定；全 K5 与失败行保留 |
| `PROPOSED_USE_DIFFERS_FROM_INPUT` / `UNASSIGNED_USE` | 用途改变或未指定，不能悄悄迁移旧研究样本 |
| `GROUP_CROSSES_USES` | 显式组跨已指定用途；unassigned 不当作合格划分 |
| `DECLARED_IDENTITY_SPLIT` / `LINKED_IDENTITY_SPLIT` / `LINEAGE_SPLIT` | 同一局部 subject、显式 linked_subject 或父子派生链被拆组；局部 subject 保持 dataset 命名空间 |
| `EXACT_FILE_CROSSES_USES` / 声明内容冲突 | 标准化文件精确组跨用途，或原 K5 的 SHA/路径/内容声明矛盾；不把声明哈希当本轮原图核验 |
| `GROUP_BASIS_UNRESOLVED` / `CANDIDATE_REVIEW_*` | 分组依据或候选审查未齐；AI自述不能消除待办 |
| `REVIEWED_DUPLICATE_SPLIT` / `EXACT_FILE_REVIEW_CONFLICT` | 已声明重复却拆组，或试图否认字节相同证据 |
| `INPUT_CHANGED_AT_FINAL_CHECK` | 约束计算后元信息或运行源码改变；不生成冻结包 |

约束后再次核对全部已读元信息 pin 及三份直接运行源码指纹。初始契约/指纹不符在创建输出前拒绝；末检变化则留下 blocked 报告及具体路径。原年龄精度/区间/null、身份/用途、曝光史及历史 NO_FACE 始终保持；历史模型失败不因本轮可读而改写为成功。

## 4. 输出与资格边界

退出0：工程声明 consistent，输出 `report.json` 与 `frozen-inputs.json`。退出1：约束或末检 blocked，只输出完整报告。退出2：契约、初始 pin、路径或预算拒绝，不产生新的输出目录。

报告含全 K5 行、逐行显式 assignment、P03状态/错误、完整依据/候选审查、阻断清单和原 K5 审计；用途/许可/身份待办不从原审计中删除。冻结包 schema 是 `agemorph3d-split-frozen-inputs-v1`，保存准确输入 pins、完整 K5、显式 assignments 和依据包，报告另存该文件准确 bytes/SHA-256。`assignment_method=explicit_declarations_only`、`random_seed=null` 表示没有运行随机划分，不伪造种子来源。

包不是正式数据冻结签收或训练清单替换。`freeze_authorized/split_assignment_performed/human_review_verified/candidate_review_complete/cross_source_identity_proven` 及正式数据、训练、独立评价、服务、生产、G3 标志均保持 false。即使约束一致，实际用途、官方/人工依据内容、当前图片完整性、身份及质量仍须分别完成。
