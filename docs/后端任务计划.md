## 3. 环境与最小架构

API独立环境和锁文件已建立。B0运行真实CPU；资产版本/条款/哈希见[模型台账](model-assets.md)和[B0记录](B0模型验证与复现.md)。BFM映射已证明，但后续年尺度比较未通过；SAM独立CUDA研究推理及常驻worker已实际运行。各环境及历史依赖变化按对应记录核验，不把研究运行当作严格服务许可或质量验收。

维持一个回环服务、单 Uvicorn worker、lifespan 管理的单模型实例、事件循环外推理和有界准入。先验证 3DDFA/BFM CPU 最小样例，再测试实际 GPU provider；不得用显卡可见或 provider 列表代替推理成功。算法依赖独立锁定，不修改系统 Python；只有实际依赖冲突或显存隔离需要得到证明后才拆独立算法进程。候选原生环境连续 2 个有效工作日无进展时，记录失败并评估本机 WSL2 路径。

不引入数据库、Redis、Celery 或账号系统。现有 `app.py/config.py/schemas.py/errors.py/images.py/middleware.py/runtime.py` 继续作为服务基础；检测、重建、GLB 编码和缓存按实际边界逐步增加适配器/组件，不为预想架构先拆空目录。真实模型放既有忽略目录 `data/models/`，推理产物与原始验证证据放 `output/backend/` 等既有忽略目录；不得把真实人像、权重或批量数据加入源码。

## 5. 已冻结契约与下一批接入

现行v1.2已实现健康状态、静态HTTP、资产发布、前端模式及WS成功/恢复路径：

- `GET /api/health`：严格加载、自检产生模型状态和实际backend/provider；HTTP200只表示服务存活。检测/重建均ready且未关闭才开放reconstruction/realtime，年龄仍false；当前真实清单未ready。
- `WS /ws/frame`：真实框、五点、纯旋转；NO_FACE/MULTI_FACE/BUSY可继续，致命错误回复后关闭。每连接seq从1开始，成功/错误均关联；不返回完整参数或逐帧GLB。当前真实清单仍MODEL_NOT_READY/1013；客户端已补1013及协议1009提示、2 MiB发送前检查与手动恢复，未取得正式G2。
- `POST /api/reconstruct`：保留 `image` 和 `mesh_id/shape/expr/pose/texture_url?`，可选上传 `source_age`；成功必需模式、结果能力、源年龄和拓扑。严格模型对 ready 时返回200静态结果，无人/多人分别422 `NO_FACE`/`MULTI_FACE`；未就绪503，忙/容量不足429。当前真实清单仍因许可返回503，不能以合成服务验证替代。
- `GET /api/assets/{mesh_id}/mesh.glb`：对应已发布canonical自包含GLB，身份/表情已应用，可选原照片基础UV；Y-up、正面+Z，bbox高度1、非人体米制标定，绕序版本固定；未登记/过期404，租约保留至发送结束，无磁盘目录挂载。
- `POST /api/aging`：保留 `mesh_id/age` 和现有 `shape_aged/texture_url?` 语义。当前 UI 的操作是纹理生成，成功必须有真实纹理；纯年龄形状随 GLB 交付。源年龄未知或尺度未校准时，不伪造绝对目标年龄。
- 现有前端本地 GLB/PNG 导出保留；服务端 `/api/export/gltf`、`/api/export/image` 不进入首个真实闭环。

请求限制和错误约定延续当前实现与 [api.md](api.md)：JPEG/PNG/WebP、单图片 ≤10 MiB/1600 万像素，multipart 总量/字段限额，真实解码和 MIME 检查，应用层稳定错误码与字符串 `detail`，应用层错误响应对合法 Origin 可读。默认回环、明确本地 Origin、无凭据、Host 与 WS Origin 分别验证。400/413/415/422/429/503/504 的测试通过不能替代成功推理与资产链路。

本轮实测发现的传输边界必须在 B1/G0 收口：Uvicorn 到达连接上限 16 时可在 ASGI 前返回纯文本 503，没有 JSON/CORS/no-store，浏览器现为通用连接失败提示；超过 2 MiB 的 WS 消息由协议层直接以 1009 关闭，没有 JSON 终结 `error`。下一批明确这两层的承诺，验证连接预算与过载可读提示；不能把应用层统一错误说明扩展为所有传输层失败都已统一。详细复现以基础服务验收报告为准。

## 6. 实时、缓存和性能验收要求

WS客户端使用JPEG二进制、最长边640、最多10FPS、单飞。服务端对实际消费的应用输入递增seq，每个至多一条face_state/error；status不确认，断连/传输失败和协议拒绝单列。NO_FACE/MULTI_FACE/BUSY后可继续；流水违规的两个已消费序号各BUSY后1013，不排队推理。bbox和有符号五点保留原JPEG像素及图像左右；精确眼中心/眼角质量未校准。视频/叠加一起镜像，三维显示S R S。消息实际UTF-8≤1024B，不传完整shape/expr。

HTTP正文接收、校验与静态重建共享25秒，发布前复查绝对截止时间；WS工作及成功发送共享6秒，发送另受1秒上限，错误/关闭各限1秒。发送前再次检查调度后的剩余预算；发送超时不重复发送终结消息。前端HTTP30秒、连接/编码/单帧8秒等待。原生线程未结束前不释放工作槽位。实际Uvicorn自动协议、读取背压与传输限制见B6记录。

资产已采用进程内不可变字节缓存，默认 TTL1800秒、总量512MiB、128项、单项64MiB。随机不可预测 `mesh_id`；成功等待并检查连接/截止时间/关闭状态后原子发布。读取租约占用容量直至发送结束或异常退出，TTL不因访问延长；空间不足时逐出未固定的 LRU，无法容纳返回429。未知/过期标识404，进程退出清空；不使用任意文件目录、服务临时 GLB 或数据库。原图/裁剪只在有界内存短暂保留。取消后丢弃迟到结果，原生算子实际结束前继续占用工作槽；配置与回归见 B2/B3 记录。

日志只记请求 ID、阶段、耗时、错误码和资源摘要，不记照片、帧、完整参数或原始文件名。硬件性能分别记录冷启动、预热后重建、纹理、WS p50/p95、视口 FPS 和峰值内存/显存。重建 ≤5 秒、视口 ≥30 FPS 仍为待测目标；软件 WebGL 自动化、10 FPS 传帧上限和模型推理 FPS 不能混报。
