## 5. 已冻结契约与下一批接入

现行 v1.2 已实现健康状态、静态成功响应的 schema/解析及前端模式；成功 HTTP/WS 和资产发布仍待接入：

- `GET /api/health`：保留 `models/device/version/api_version/capabilities`。已由严格加载与自检产生单模型状态和实际 backend/provider；HTTP 200 只表示服务存活。端到端链路未交付前四项能力均 false，后续按实际成功链路开放。
- `POST /api/reconstruct`：保留 `image` 和 `mesh_id/shape/expr/pose/texture_url?`，可选上传 `source_age`；成功契约必需 `asset_mode: static | age_morph`、结果能力、源年龄和 `topology_id`。类型/校验已同步 schema、前端、文档与测试；静态必须显式声明，损坏的年龄资产不能自动降级。端点本轮仍503。
- `GET /api/assets/{mesh_id}/mesh.glb`：真实发布后返回 canonical、自包含 GLB；身份/表情已应用；固定右手 Y-up、正面 +Z、拓扑及单 UV。未登记/过期/损坏保持可解释失败，不挂载任意文件目录。
- `POST /api/aging`：保留 `mesh_id/age` 和现有 `shape_aged/texture_url?` 语义。当前 UI 的操作是纹理生成，成功必须有真实纹理；纯年龄形状随 GLB 交付。源年龄未知或尺度未校准时，不伪造绝对目标年龄。
- 现有前端本地 GLB/PNG 导出保留；服务端 `/api/export/gltf`、`/api/export/image` 不进入首个真实闭环。

请求限制和错误约定延续当前实现与 [api.md](api.md)：JPEG/PNG/WebP、单图片 ≤10 MiB/1600 万像素，multipart 总量/字段限额，真实解码和 MIME 检查，应用层稳定错误码与字符串 `detail`，应用层错误响应对合法 Origin 可读。默认回环、明确本地 Origin、无凭据、Host 与 WS Origin 分别验证。400/413/415/422/429/503/504 的测试通过不能替代成功推理与资产链路。

本轮实测发现的传输边界必须在 B1/G0 收口：Uvicorn 到达连接上限 16 时可在 ASGI 前返回纯文本 503，没有 JSON/CORS/no-store，浏览器现为通用连接失败提示；超过 2 MiB 的 WS 消息由协议层直接以 1009 关闭，没有 JSON 终结 `error`。下一批明确这两层的承诺，验证连接预算与过载可读提示；不能把应用层统一错误说明扩展为所有传输层失败都已统一。详细复现以基础服务验收报告为准。

## 6. 实时、缓存和性能验收要求

WS 客户端仍用 JPEG 二进制、最长边 640、最多 10 FPS、单帧等待。服务端对进入应用的 ≤2 MiB 帧递增 `seq`，每帧只发一条 `face_state` 或 `error` 终结消息；`status` 不算确认。协议层拒绝的超大帧按关闭码另验。`NO_FACE/MULTI_FACE` 接入后是可继续错误，其余严重错误明确关闭。`bbox=[x,y,width,height]`、五点都对应收到的原 JPEG，固定眼中心/眼角、左右和镜像定义；不能把 ROI 坐标直接返回。用 UTF-8 实际编码验证 ≤1024 B，不重复传完整 shape/expr。

HTTP 当前正文接收和校验共享 25 秒预算，WS 工作默认 6 秒；后续根据真实模型测量调整，仍为前端 30 秒 HTTP/8 秒单帧等待留出返回时间。慢纹理任务不能阻塞事件循环或积压实时队列。必要时先设计新异步协议，不能静默等待数分钟。

资产初始建议为 TTL 30 分钟、派生文件容量 512 MiB，均是 B7 待实测配置。随机不可预测 `mesh_id`、单缓存根目录与路径校验、临时写入后原子发布、读取中的文件不清理、失败/取消/重启清理分别测试。原图/裁剪只在有界内存短暂保留。调用方取消后丢弃迟到结果；已进入 GPU 的算子不保证立即停止，槽位实际释放与结果不再发布分别验证。

日志只记请求 ID、阶段、耗时、错误码和资源摘要，不记照片、帧、完整参数或原始文件名。硬件性能分别记录冷启动、预热后重建、纹理、WS p50/p95、视口 FPS 和峰值内存/显存。重建 ≤5 秒、视口 ≥30 FPS 仍为待测目标；软件 WebGL 自动化、10 FPS 传帧上限和模型推理 FPS 不能混报。
