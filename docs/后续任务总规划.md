## 2. 最终要交付的系统

用户在本机选择照片或拍照，系统真实检测人脸，恢复对应的参数化三维人脸，显示基础纹理；有经过验证的年龄能力时，可在 20—70 岁间调节形状，按需生成年龄纹理，并导出包含当前结果的 GLB 与 PNG。摄像头模式实时展示真实框、关键点和姿态；缺模型、无人脸、多人脸、无效输入、超时等状态可解释、可恢复。

最终论文要能回答三个问题：系统是否真实可用；检测和年龄方法相对明确基线有何表现；效果、速度、身份保持和数据偏差之间有哪些取舍。完成训练不等于结果一定优于预训练模型，应如实报告改进或负面结果。

### 2.1 范围分层

| 层级 | 必须规划的内容 | 截止或降级规则 |
|---|---|---|
| 核心工程 P0 | 本地 API、YOLO 人脸检测、可靠 5 点来源、真实重建、单一拓扑、静态/年龄能力、GLB/PNG、实时姿态、设备与异常验证 | 缺年龄能力时可先验收真实静态重建；最终题目是否允许降级须与导师确认，不能自行宣称全部完成 |
| 核心研究 P1 | 检测预训练/微调对照、年龄形状基线与回归实验、纹理验证、消融、锁定测试集、实验与论文 | 微调/回归不稳定时保留已验证基线，并记录失败证据；纹理失败则相关功能及任务书符合性仍待解决 |
| 增强 P2 | MICA/FLAME 第二拓扑、客户端形状基、独立 manifest、逐帧表情几何、五点联合训练、额外 ONNX/量化优化 | 仅当核心出口通过、仍有明确收益和剩余时间才实施；不进入交付关键路径 |

保持三条范围约束：研究的是年龄变换；目标年龄 20—70；照片与摄像头在本机处理。演示使用获准使用的成年人照片。局部人脸表面不表述为完整头部；当前实时姿态不表述为逐帧完整几何重建。

### 2.2 六个必须提前解决的问题

1. **前端静态模式已实现。** `static/age_morph`、源龄、控件和导出语义已有契约与回归；后续补严格G1和最终交互签收。不能用零位移假装年龄能力。[相关源码](../frontend/src/viewer.ts)
2. **固定一种拓扑。** 第一条完整链路先用经过验证的 3DDFA/BFM 资产。记录顶点序、三角面、基、UV、单位和哈希；BFM/FLAME 不混用，顶点数相同也不能证明顶点序相同。
3. **BFM映射完成，年份尺度未通过。** 原生199维属性到当前裁剪基的精确映射已验证；留一身份校准出现负系数且未优于静态，不能把研究强度当岁数。下一步在同基数据接口上冻结新回归候选。[研究结论](年龄形状路线比较与研究校准.md)
4. **绝对年龄锚点。** 照片形状已含其当前外观年龄，不能默认属于 45 岁。定义 `source_age` 的来源与不确定性：受试者提供、经验证的独立估计器，或仅可称相对年龄强度。未校准的属性强度不能声称每单位等于一岁。
5. **姿态转换已实现，真实质量待收口。** 后端已用SVD提取纯旋转并检查正交/反射，GLB保持canonical；实体相机研究证据已有，仍需正式服务、有意转头和长时恢复验收。[B6记录](B6实时姿态开发记录.md)
6. **纹理工程链已运行，质量未通过。** 真实SAM、目标自有重建/投影、可见性与mask、共同UV、独立会话和原始恢复已实现；眼区/侧面/接缝、身份与年龄质量、稳定浏览器仍待解决。二维生成成功不能替代这些出口。[真实候选结果](真实额头候选注册与质量复核.md)

## 5. 后端与联调怎么做

详细 B0—B8 见 [后端计划](后端任务计划.md)；新增统一任务编号 R01—R14 见 [任务清单](后续任务清单.md)。执行顺序是环境/协议并行，真实检测/重建后汇合，最后进入实时和年龄模块。

v1.2健康状态`missing/loading/ready/error`、结果级`asset_mode`、能力和`source_age`已落地；缺模型503、静态不贴虚构年龄等语义继续保持。后续不重新实现整套协议，重点核验严格真实成功链、具体用途和未完成的传输/资源出口。年龄生产入口仍为`MODEL_NOT_READY`。

重建内部结果、canonical几何、纯旋转、ROI/投影、形状/表情及来源哈希和GLB已有实现。K1将已有原图拟合整理为规范研究特征数据，保持这些绑定；算法适配器仍不直接操作页面状态。

第一版保持现有限额：图片 ≤10 MiB/1600 万像素；GLB ≤64 MiB/150 万顶点；纹理 ≤16 MiB/1600 万像素；JSON ≤128 KiB；HTTP/资产前端等待 30 秒；WS 回复 ≤1024 UTF-8 字节、等待 8 秒、最多传 10 FPS。服务端独立检查输入并设置更早的内部截止时间；超过现有协议预算则明确失败，异步任务协议另行设计。

输入仅接受文件内容；服务绑定回环，CORS 与 WS Origin 独立校验。模型单实例、推理离开事件循环、任务队列有界、资产 TTL/容量可配置。取消和断开后丢弃迟到结果；不承诺中断已经提交的 GPU 算子。照片与帧不进日志，随机 mesh ID 不含姓名，缓存不持久保存原图。

## 6. 获取哪些数据，怎样控制工作量

资源选择、出处与限制详见 [模型与数据路线核验](模型与数据路线核验.md)。采用最小组合，先小样核验再批量；不同时获取所有候选。

| 用途 | 首选/候选 | 最小必要工作 | 不应误用 |
|---|---|---|---|
| 检测微调 | WIDER FACE | 官方划分、框转换、Easy/Medium/Hard AP 评价 | 不把它当 5 点标注来源；不把 AP 写成随意口径的 mAP |
| 重建评价 | AFLW2000-3D；3DDFA 相关数据协议 | 复现明确的关键点/姿态/归一化协议 | 不称其逐顶点激光扫描真值；不重新训练完整重建器作为首要任务 |
| 年龄精细回归 | UTKFace 候选 | 20—70 标签筛选、质量检查、年龄分布、身份泄漏限制 | 标签不等于身份证年龄；缺身份标签时不能声称严格身份隔离 |
| 年龄分布补充 | FFHQ-Aging 候选 | 年龄区间和置信度；成人区间筛选 | 区间标签不伪造成逐岁真值；70+ 不整体当作 70 岁 |
| 同人跨龄检查 | 已有FG-NET成人292图/55身份；另需获准外部数据 | 保留10开发/15校准/30研究保留，披露全部历史预处理接触 | 现有子集不是独立外部测试，不能靠改组补高龄覆盖或宣称训练完成 |
| 五点联合训练 | WFLW/300W-LP 等候选 | 只有实际需要时增加，固定 68/98→5 的定义 | 不让额外关键点训练阻塞已有可靠五点来源 |

每份资产记录：来源、版本、代码和数据/权重各自条款、允许用途、取得状态、大小、SHA-256、存储位置、处理版本和再分发限制。仓库 MIT 许可证不改变第三方资产的许可；需要登录或申请时记录负责人和等待状态，不代替用户同意条款。

下载先取可合法取得的小样做格式/许可/解码验证；磁盘需求按实测压缩包、解压、处理结果、检查点估算，再增加余量。不要在未确认空间和用途时下载全部高分辨率 FFHQ。获取失败保持失败记录，替换来源必须重新核查。

## 7. 预处理与实验怎样保证可信

### 7.1 数据管线

原始数据只读保存；每条记录关联来源 ID、SHA-256、年龄或年龄区间、身份/分组依据、质量状态和排除原因。训练/验证/测试采用公开协议或预注册划分；小样通过后才全量运行。

现有N0是研究用途划分，已有校准、诊断结果被观察，不能直接改名为正式train/val/test。K1只整理既有70原图校准拟合的shape40及失败/用途/来源，不运行新模型或读取保留组图像；后续正式划分须另有获准数据和冻结协议。当前`preprocessing/`已实现K1，50项新增及真实JSON集成已完成，详见[下批具体范围](剩余关键工作开发计划.md#5-下一开发批次的具体范围)。

先建立身份与重复组，再生成划分：精确哈希去重、近重复审查、可信 subject 分组优先。缺身份标签可用保守的相似度分组辅助隔离，标为“近重复/推测身份组”，不能声称已验证真实身份。完整数据级去重只用于防泄漏，不拟合模型；归一化、阈值选择及其他可学习量只在训练/验证职责内确定。

对齐时记录原图→裁剪→模型→渲染坐标变换，翻转同步变换框和点。年龄任务只使用 20—70 的有效标签；检测任务按其许可与协议处理，不能假定无年龄标注的检测集全是成人。低质量筛选规则先冻结，报告每组排除比例，避免选择性删掉困难测试样本。

用固定重建器提取同一形状基的系数，绑定拓扑/基/权重/预处理哈希。采用可续跑任务清单；成功和失败都可追溯，不用零向量填失败样本。训练输入使用身份形状，表情/姿态作为控制项或质检依据，不把表情误当年龄方向。

### 7.2 先做基线，再做有边界的训练

1. 冻结预训练检测、重建和可用年龄属性的基线，记录质量、速度与资源。正式测试集尚不用于调参。
2. 微调人脸检测器，固定划分，验证集选择训练时长/阈值；与相同推理设置下的预训练权重比较。只有必要时训练五点分支。
3. 年龄形状先做线性/Ridge 基线，再做小规模改进，例如置信加权、质量筛选或分段年龄方向；固定一个主要改进问题，不同时引入多种新模型。
4. SAM 只评估预训练推理与 UV 集成。batch=1、实际峰值显存、旧算子兼容先出数；单纯输出缩小不证明生成器显存下降。必要时调整确实改变计算图的方案并重新验证，不自动转云。
5. 选定模型后冻结配置，再做最终测试。结论不足时保留基线，失败实验仍记录，避免只报告最好的一次。

建议在训练形状空间拟合 `βᵢ = b + (aᵢ − ā_train)d + εᵢ`，对 `d` 正则化；尺度和任何统计量只在训练集拟合。生成候选为 `β_target = β_input + (a_target − a_source)d`，并限制位移幅度。此式是待验证的群体关联模型，不保证得到个体真实纵向变化；人群、体重、表情与重建偏差须作为局限和敏感性实验。

若只有年龄区间，使用区间/分组训练目标或独立实验，不把区间中点当精确真实标签后混报逐岁误差。官方 BFM 属性若没有年尺度校准，只能先提供相对方向原型；源年龄与方向尺度的误差要分别测试。

## 8. 评价与验收矩阵

| 维度 | 协议与指标 | 最终必须留下的证据 |
|---|---|---|
| 检测 | 官方 WIDER Easy/Medium/Hard AP；固定分辨率、NMS、阈值与设备；耗时单列 | 预训练/微调同协议结果、PR 曲线、失败样例、原始预测摘要 |
| 重建 | 官方/明确实现的 NME、点集和归一化方式；姿态分组；检测失败率单列 | 原始与适配实现一致性、坐标检查、样例投影；不跨协议引用某个百分数 |
| 年龄符合度 | 独立年龄估计器的代理 MAE/区间符合度、目标年龄曲线 | evaluator 版本/哈希、适用样本数、校准和不确定性；不用训练损失网络充当独立真值 |
| 身份保持 | 固定人脸对齐、视角、光照、渲染裁剪；身份 embedding 相似度 | 原图/输出可比条件、按受试者汇总；不预设通用相似度阈值 |
| 形状与纹理 | 原始重建、仅形状、仅纹理、二者结合；可用时再比较回归改进 | 同一批样例与固定视角；正/侧面、UV、穿插、法线、连续性与身份影响 |
| 系统 | 冷启动、热重建、纹理、WS p50/p95、渲染 FPS、载荷、峰值内存/显存 | 热身/采样次数、分辨率/provider、原始时序；≤5 秒/≥30 FPS 为待测目标 |
| 交互与交付 | Chrome/Edge、真实摄像头、错误恢复、GLB 再导入及 Blender、离线启动 | 可复现检查记录，软件 WebGL 自动化不冒充硬件性能 |
| 主观评价 | 有条件时邀请 10—20 名成年评价者、匿名盲测、打乱顺序、两个维度评分 | 同意说明、样本与问题、分布和局限；这是建议样本量，不是学校确认要求 |

最终测试协议在模型选择前冻结。按受试者而非相关图片估计不确定性；缺身份标签时说明区间估计的限制。形变权重要求连续，**不要求每个顶点随年龄单调移动**；年龄趋势看整体代理与人工检查，不能由插值数学自动证明。

WIDER 默认从官方 train 内部划开发集选 checkpoint/阈值，将官方 val 留作冻结后的阶段评价；若实际改用官方 val 调参，结果就标“官方验证集 AP”，不能据此主张独立 test。没有官方测试服务器结果时，保留测试状态未完成，不用本地 val 冒名。

## 9. 两个人怎么协作

| 角色 | 主责 | 对方必须交叉复核 |
|---|---|---|
| A：算法与实验 | 资产验证、检测/重建/年龄适配、数据与训练、算法评测 | B 用独立环境重现模型样例，检查坐标/拓扑/结果可用性 |

| 共同 | 数据/模型条款、拓扑冻结、实验协议、例会、论文接口与个人贡献 | 每一出口都由另一成员按记录检查，不能由实现者单独口头完成 |

角色是分工建议，尚未绑定姓名。每个任务只有一名主责，另一人做审查；一块 GPU 上训练、批量重建、SAM 推理排队执行，不同时争抢显存。系统侧可用明确的合成夹具开发，但正式运行缺模型时返回未就绪。

每周一次 30—45 分钟例会，记录：完成的任务 ID/证据、本周出口、阻塞及负责人、接口变化、GPU 预约。进行中的大任务每人最多一个；技术探索连续 2 个有效工作日无结果即记录并选替代路径，避免无限配置环境。

分支按实际任务建，例如 `codex/r06-capabilities`、`codex/t03-age-direction`。变更经对方审查再集成；本地小组规则仍要求 Git 写操作前读取忽略规则、敏感扫描并确认精确文件范围。每次发布检查完整树及历史中会传送的内容，不能只核对最后一次提交的文件。
