# 固定长度响应兼容候选审查

2026-10-25。结论是撤回原生读取候选，保留现有按实际字节计数的客户端。Chrome、Edge 的 HTTP/2 代理实测表明：即使 HTTP loopback、跨源 `cors`、无 Service Worker、完整暴露长度/编码头、无编码且声明长度小于预算，`arrayBuffer()` 仍可返回超预算数据。稳定版研究会话验收继续未通过；本批没有模型推理、生产能力变化或 Git 操作。

## 范围与判断

本批按[前瞻协议](research-framed-response-v1.json)调查原稳定版 `no-store` 流读取的完成标记问题。该协议保留原候选条件，不因结果改写为已通过协议。实验仅使用本机合成字节、独立浏览器上下文及自有服务器，不读取本人照片、权重或评价保留组，不修改系统浏览器、代理、证书存储或项目依赖。

旧网络问题与[Playwright 官方问题42742](https://github.com/microsoft/playwright/issues/42742)的症状一致；本批未独立捕获完整 Blink 原生调用栈，不将症状相同宣称为完整因果证明。研究服务的原 `no-store`、字节预算、超时/取消和未知源龄规则全部保留。

| E3：[严格SW控制](../output/research/framed-response-20261025/sw-guard-1792933233275/report.json) | 两浏览器各5例控制行为断言通过：basic合成响应不选native、超预算块在保留前拒绝；真实controller变化中止未完成读取，读取后变化也拒绝发布。Edge的SW网络转发例仍有1次ERR_ABORTED，数据正确 | `cors`与上下文检查解决这组SW反例，不解决传输或网络验收问题。读取后检查使用明确标注的人为异步插入 |

| E6：[固定源码双浏览器流替代矩阵](../output/research/framed-response-20261025/stream-alternatives-1792934335778/report.json) | 两浏览器各72例：pipeTo、BYOB、真实SDK各16条正向长度/哈希全正确；另24负例全拒。完成标记失败数分别为Chrome 8/5/8、Edge 8/8/5；三源码前后pin相同 | 三种路径均未满足网络出口。状态为observed-completion-defect-not-accepted，主动退出1；服务正常退出0 |

路径P1为 `HTTP URL → 本机HTTPS代理协商H2 → cors响应 → 原生arrayBuffer → 完整超预算payload`，对应E4；不是本机服务常规网络设置的描述，而是网页条件无法排除的受支持路径。代理没有转发到外部服务，未发送私人研究输入。该实验使用浏览器进程内临时代理/证书测试参数，退出后监听关闭、临时私钥删除，见[清理收据](../output/research/framed-response-20261025/security-review/cleanup.json)。这些测试参数没有写入产品配置。

路径P2为现有 `fetch → getReader → 累计实际chunk长度 → 预算检查 → 保留副本 → EOF及长度检查 → 解析`。E2—E4的负例支持保留这一边界；边界针对应用保留和发布的响应payload，不是浏览器网络内部缓冲或进程RSS上限。不能通过读取后的长度检查补救已完成的超预算原生消费，也不继续添加未经证明的头部条件来掩盖反例。

## 源码与标准依据

精确Chrome revision的[HTTP/1 parser](https://chromium.googlesource.com/chromium/src/+/d0c02bfad08ec92a6ffcf989e53cd995e6381a4c/net/http/http_stream_parser.cc)在返回前扣除长度外的数据；[HTTP流选择](https://chromium.googlesource.com/chromium/src/+/d0c02bfad08ec92a6ffcf989e53cd995e6381a4c/net/http/http_stream_factory_job.cc)同时允许HTTP目的地址经HTTPS代理使用H2。因此URL scheme不能证明将采用前述parser。保存源码及下载收据见[独立审查](../output/research/framed-response-20261025/security-review/review.md)。Edge公开精确revision取得失败，只报告实测行为，不宣称审阅了Edge精确源码。

[RFC 9112](https://httpwg.org/specs/rfc9112.html#message.body.length)描述HTTP/1消息长度与额外数据处理；[Fetch标准](https://fetch.spec.whatwg.org/#concept-filtered-response-cors)描述CORS过滤和内部body。二者不能单独推出所有UA、传输和解码响应的原生读取预算保证。前瞻JSON中旧Fetch锚点未命中当前页面，此处链接更正，原冻结文件保留。UA和主版本也不能认证二进制实现或排除代理设置。没有为拒绝此候选再扩展H3实验。

实际 `_LeasedResponse` 已经通过 `Response.__call__` 单次发送ASGI body；把单次发送再作为“新修复”没有代码依据，也不保证只有一次底层网络写入。

## 撤回与当前状态

候选SDK、合成测试和CORS头改动均先留存本机快照，再精确撤回。四文件与先前v6冻结快照逐字节相同，见[SDK撤回记录](../output/research/framed-response-20261025/client-native-withdrawn-20261025T130314325177Z/withdrawal.json)及[后端撤回记录](../output/research/framed-response-20261025/backend-candidate-withdrawn/withdrawal.json)。候选前端未执行测试或模型；后端临时75项通过包含两项随后撤回的测试，不能说当前新增75项或当前新增原生兼容能力。

首次fixture误设重复CL及超时预算、SW单块大小断言错误，连同两轮流替代方案的失败均保留。后端撤回后的首份收据因默认GBK读取JSON失败，源码已恢复；随后仅修收据读取编码并完成hash核验，不把记录错误当应用缺陷或通过证据。

独立首份终审曾复核E5的样本数字，却遗漏其SDK中间版本pin及缺少终检，不能用该审计倒推精确基线。发现后已披露并另运行E6，没有覆盖初轮报告或把新结果写回旧轮。E6只加载固定源码和合成字节，没有模型、私密照片或生产配置变化。

原Chrome/Edge真实worker、会话、显示和资源出口仍未签收。此前固定Canary158+SwiftShader+软件合成的12帧证据继续只适用于该配置，见[会话显示记录](真实研究会话连续显示与导出记录.md)。下一步保留稳定版重验入口，同时推进不依赖该网络缺陷修复的纹理支持、身份/年龄本域校准、独立数据和许可工作；不降低原验收条件。G3、生产及全部年龄/身份/视觉质量资格保持关闭。
