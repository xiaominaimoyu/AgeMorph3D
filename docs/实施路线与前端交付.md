# AgeMorph3D 实施路线与前端交付

更新日期：2026-10-18。

本文按本次任务确定的顺序推进：**前端 → 后端 → 获取训练集 → 数据集预处理 → 训练**。既有《项目计划》《技术框架与模块行动计划》和 `design/` 保留；其中的旧排期、依赖版本声明和量化目标不能直接视作当前验收结果。

## 当前状态与边界

前端工作台已实现，并通过本次类型检查、生产构建、单元测试和 Chrome/Edge 浏览器自动化验证。后端推理、训练集获取、预处理、模型训练尚未交付。演示头模由前端程序生成，支持连续形变和交互，但与用户上传照片无身份对应关系。界面及导出内容保留演示标识。

三条项目边界保持一致：目标年龄 20—70 岁；进行年龄变换而非个人未来容貌预测；照片和摄像头数据仅在本机处理。应用不将数据发送到云端，也不为绕开显存限制自动切换远程推理。

## 第一阶段：完整前端

**目标**：在没有算法环境的机器上运行完整交互，形成后端可以接入的具体界面与接口契约。

采用 Vite + 原生 TypeScript + Three.js，延续深蓝底色、青至琥珀年龄轴、细线分隔及等宽数值。页面以操作工作台为主，原设计稿作为视觉参考。

| 功能 | 交付内容 | 出口检查 |
|---|---|---|
| 输入 | 本地照片选择、拖放、预览、移除；摄像头开启、拍照、关闭 | 无效图片有反馈；切换来源时清理旧状态；媒体流被释放 |
| 演示 | 程序化头模与明确的演示说明 | 无后端可运行；不声称图片已完成重建 |
| 年龄 | 20—70 岁滑块、数值与快捷档位；三档分段插值 | 端点和中间值连续；无越界权重 |
| 三维查看 | 旋转、缩放、复位、视角、材质、光照；固定年龄对照 | 控件可用；对照视角和目标视角行为一致 |
| 导出 | 当前视图 PNG、含模型和形变的 GLB | 文件可下载、内容非空；GLB 可重新加载 |
| 本地服务 | 服务地址校验、健康检查、重建请求、加载/失败状态 | 不接受远程主机；失败不冒充成功 |
| 实时显示 | 摄像头帧发送、框/5 点叠加、姿态驱动 | 有服务时按序处理；无服务时不伪造检测结果 |
| 可访问性 | 键盘、可读标签、焦点、状态提示、减少动态效果 | 关键流程可用键盘完成，触控目标足够大 |
| 响应式 | 桌面工作台、窄屏堆叠 | 无页面级横向溢出，控制器不遮挡画布 |

验证命令在 `frontend/` 下执行：

```powershell
npm ci
npm run build
npm test
npm run test:e2e
```

验收记录须区分：编译/类型检查、自动化交互、实际浏览器画面、真实摄像头、真实算法联调。上述检查在完成前一律标为待验证；自动化中的模拟摄像头或测试服务不能替代真实设备和算法验收。

当前资产契约先接收自包含 GLB，要求内嵌 `age_20`、`age_45`、`age_70` morph target。原方案中的独立 `.bin` manifest 加载器、形状基客户端重建和逐帧 `shape/expr` 应用不作为本阶段已交付能力；后端需将本次身份形状与表情应用到返回的网格中。详见 [api.md](api.md)。

**出口**：构建、单元测试与浏览器交互检查有实际结果；演示输入、三维、年龄、导出、错误恢复构成完整闭环；尚需真实服务/设备才能验证的项目单列。

## 第二阶段：本地后端

**目标**：FastAPI 为前端提供稳定的本机 API，随后接入预训练算法，不先承诺训练后效果。

1. 建立配置、请求校验、健康检查、统一错误码、HTTP 与 WebSocket 骨架。服务绑定回环地址；CORS 只允许明确的本地前端来源；日志记录耗时和错误，不记录照片或敏感请求体。
2. 按 `docs/api.md` 实现契约测试与测试资产。真实推理尚未接入的响应必须标识其模式，不以固定结果伪装模型输出。
3. 跑通检测预训练权重与 3DDFA_V2 重建，记录模型来源、许可、实际运行依赖、设备和耗时。MICA/FLAME 作为候选增强路线，在许可和运行条件具备后评估。
4. 固定一种拓扑，生成包含身份形状与年龄 morph target 的 GLB。核对顶点顺序、右手 Y-up 坐标、尺度、UV 和姿态变换。
5. 接入年龄形状与可选纹理服务。慢任务与实时帧分离；WebSocket 单飞、丢弃旧帧、断线后可恢复；模型实例不随请求复制。

“实时包小于 1 KB”仅约束服务端实时参数消息，客户端 JPEG 帧和一次性 GLB 不在此范围。完整形状/表情不应在每帧重复发送；实际序列化大小必须测量。

**出口**：照片 → 真实检测 → 真实重建 → 年龄调节 → GLB/PNG 形成闭环；无人脸/多人脸/超时等有真实错误反馈；记录端到端耗时、渲染表现和传输量。≤5 秒与 ≥30 FPS 是待测目标，不能写成未测事实。

## 第三阶段：获取训练集

**目标**：获得许可清楚、来源可追溯、用途匹配的数据和模型资产。

| 用途 | 候选资源 | 获取前必须核验 |
|---|---|---|
| 人脸框检测 | WIDER FACE | 官方入口、访问条款、官方划分与标注格式 |
| 5 点训练 | WFLW / 300W-LP | 许可、关键点定义、从 98/68 点到 5 点的映射 |
| 年龄方向 | UTKFace / FFHQ-Aging | 许可、年龄标签来源、成年范围、身份信息是否足以隔离 |
| 重建评价 | AFLW2000-3D | 评价协议、模型/标注许可、坐标系 |
| 同人跨龄对照 | FG-NET | 允许用途、按身份划分、仅使用符合本项目年龄范围的样本 |
| 模型与形状基 | 检测权重、3DDFA_V2、BFM、FLAME、SAM | 代码许可与权重/数据许可分开检查，申请条件和再分发限制 |

资源清单应包含来源链接、版本/发布日期、许可、申请状态、文件大小、SHA-256、存储位置和可用范围。未取得授权或来源不可核实的资产不进入后续训练。下载只使用已核验的官方入口或其明确指向的镜像，失败后保留失败状态，不静默换来源。

模型与完整数据集存放在 Git 忽略的目录或仓库外，代码只记录清单和获取方法。实际获取时再次核验依赖版本、权重名称和许可证，不能直接复制旧文档中的时间敏感声明。

**出口**：每项实际使用资源都有来源、许可和哈希记录；抽样解码与标注读取通过；原始数据只读保存。

## 第四阶段：数据集预处理

**目标**：产生可复现的训练/验证/测试划分，避免身份泄漏、重复图片和标签污染。

1. 校验文件与标注，清除损坏样本、异常框和无效年龄；年龄方向任务只保留 20—70 岁有效标签。记录每一步排除数量和原因。
2. 对人脸框做坐标格式转换；对关键点明确顺序、可见性和缺失标记。WIDER FACE 只提供框，不能凭空生成真实 5 点标签。
3. 计算文件哈希并去除跨划分精确重复，辅以感知相似度发现重编码、裁剪等近重复；保留复核记录。
4. 优先采用官方划分，并检查身份和重复交叉。年龄任务按受试者隔离，不能把同一个人的不同年龄照片随机分到训练与测试。缺少可靠身份标签的数据只能说明其限制，不能声称已达到严格身份隔离。
5. 归一化、回归和阈值等可学习统计量只在训练集拟合。固定随机种子与样本清单，测试集保持锁定。
6. 使用固定重建模型批量提取形状参数，记录模型哈希、预处理配置、成功/失败状态与年龄分布；保持单一拓扑与维度，不混合 BFM/FLAME 参数。

**出口**：转换脚本可重复运行；标签抽样叠加可视检查通过；无跨划分精确重复；身份隔离方法、无法验证的部分和分布偏差均有明确记录。

## 第五阶段：训练与评测

**目标**：用可复现实验证明改进，并保留能运行的基线路径。

1. **基线先行**：记录预训练检测、重建、BFM 年龄方向的实际指标和资源消耗，作为后续对照。
2. **检测微调**：使用官方划分训练框检测；如需单模型输出 5 点，单独实施关键点训练，分别报告框指标和关键点误差。
3. **年龄方向回归**：基于训练集形状参数拟合年龄方向，验证集选择正则化强度与位移幅度。与 BFM 基线、仅形状、仅纹理及二者结合进行对照。
4. **纹理增强**：先评估 SAM 预训练推理与 UV 贴回效果，不将大规模生成模型从头训练作为笔记本交付前提。实际显存不足时降低分辨率/批量，保持本地数据边界。
5. **最终评价**：冻结配置后一次性评测锁定测试集；记录检测精度、重建误差、年龄符合度、身份保持、渲染/推理耗时和失败案例。年龄估计器与身份评价器是测量工具，不代表事实真值。

每次实验记录配置、代码版本、种子、数据清单哈希、权重哈希、环境和设备。训练结果不自动覆盖可运行基线。

**出口**：首先通过网格拓扑与 morph 顺序检查；随后通过年龄连续性、形变幅度、身份保持和可视质量检查。年龄方向表现不稳定时保留 BFM 基线，将回归结果作为实验而非默认产品输出。最后完成前后端回归与导出兼容性检查。
