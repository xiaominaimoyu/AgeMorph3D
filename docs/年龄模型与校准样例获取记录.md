### 2.2 结构检查

用 Python 标准库 `zipfile`/`pickletools` 只读检查，没有加载模型：

- 是合法的 PyTorch zip checkpoint，共 1,416 个 zip 条目；
- 顶层键为 `state_dict`、`opts`、`latent_avg`；
- `state_dict` 含 `encoder.*`、`decoder.*`、`pretrained_encoder.*` 前缀，`opts` 中出现 `ffhq_aging`、`target_age` 等标记；
- 因此主 checkpoint 已包含推理所需的 pSp 编码器、StyleGAN 解码器、平均潜码和 `start_from_encoded_w_plus` 所需的预训练编码器；README 另列的 pSp、FFHQ StyleGAN、IR-SE50、VGG age classifier 是训练/初始化辅助模型，本次未下载。

### 2.3 许可判断

- 仓库代码：MIT。
- 预训练权重：官方仓库没有单独声明 checkpoint 的许可。README 的 MIT 徽章和 `LICENSE` 只覆盖代码，不能自动证明权重可商用。
- 训练数据：README 说明模型在 FFHQ 上训练；FFHQ 数据集及其派生元数据采用 **CC BY-NC-SA 4.0**，单张图片还继承各自的 Flickr 许可（含非商业条款）。因此当前按 **非商业研究用途、许可未收口** 处理。
- 不将 checkpoint 放入 `backend/model-manifests/`，不改变严格服务加载结果；服务年龄能力仍为 `false`。

### 2.4 本机运行状态（2026-10-20 补充）

已在独立环境 `data/envs/sam` 跑通最小 batch=1 推理，未改动 `backend/.venv`：

- Python 3.11.16 + torch 2.11.0+cu128；cu128 是 RTX 5060（sm_120）的硬要求，旧 cu121 wheel 会报 “no kernel image”。
- 本机没有 CUDA Toolkit/nvcc，StyleGAN2 的两个 JIT 算子改用 `tools/sam_native_ops/` 的原生 PyTorch 替代；对显式循环参考实现的最大误差 1.4e-6。
- `models/psp.py` 的 checkpoint 加载显式改为 `weights_only=False`；torch ≥ 2.6 的默认 `weights_only=True` 会拒绝含 `opts` 的 checkpoint。
- 1024×1024 输出，稳定前向约 0.12 s，峰值显存约 2.7 GB；另起进程重跑同一目标年龄，PNG 逐字节一致。

完整环境、安装命令、输出哈希与限制见 [SAM 独立环境配置](SAM独立环境配置.md)。这只是二维图像可行性验证：没有做 FFHQ 对齐桥接、UV 注册、身份分组评价或年尺度校准，服务年龄能力仍为 `false`。

### 3.2 数据统计

文件名同时编码身份号和拍摄年龄，例如 `078A11.JPG` 表示 78 号人物 11 岁时的照片。镜像页给出了同一解释；本次没有用出生日期独立复核。

| 范围 | 图像 | 身份 | 年龄 |
|---|---:|---:|---|
| 全量 | 1,002 | 82 | 0—69 |
| 20—70 岁子集 | 292 | 55 | 20—69 |

20—70 子集按十年分布：

| 年龄段 | 图像数 |
|---|---:|
| 20—29 | 144 |
| 30—39 | 79 |
| 40—49 | 46 |
| 50—59 | 15 |
| 60—69 | 8 |

55 人中 48 人至少有 2 张 20—70 岁图像，43 人至少有 3 张，最多 12 张；可用于同人跨龄的配对检查，但 50 岁以上样本很少，且没有 70 岁样本。该子集**不足以单独拟合稳定的逐岁回归**，更适合作为外部一致性检查、失败案例审查和校准流程的第一批真实标签样例。

### 3.3 许可与使用边界

- 当前登记状态：`research-only-unresolved`。
- 允许：本地、非商业、学术研究；格式/解码/检测/对齐/校准流程验证。
- 不允许：再分发图像或派生副本、商业使用、把镜像页表述当作正式授权。
- 不将 FG-NET 放进训练集；尤其不能把同一身份的不同年龄照片随机分到训练/测试，也不能用它调完参再声称独立测试。
- 若论文或产品需要可再分发/商用数据，必须改用有明确商用许可的数据集，或取得 FG-NET 权利方的书面许可。

### 3.4 复现命令

```powershell
curl.exe -L --retry 3 -o data/datasets/fgnet/FGNET.zip "http://yanweifu.github.io/FG_NET_data/FGNET.zip"
python tools/fgnet_manifest.py --zip data/datasets/fgnet/FGNET.zip --out data/datasets/fgnet
```

脚本只写入 `data/datasets/fgnet/`，重新计算归档和逐图 SHA-256，生成 `all-images.csv`、`adult-20-70.csv` 和 `manifest.json`；已存在且大小一致的图像不会重复写入。

### 3.5 解码/检测/68 点一致性检查（2026-10-20）

工具：`tools/fgnet_pipeline_check.py`；报告：`output/research/fgnet-pipeline-20261020/report.json` 与同目录 `per-image.csv`（`output/` 不随源码提交）。检查复用服务的 `decode_image`、YOLO5Face ONNX 检测器和 3DDFA ONNX 重建器；两个模型清单都以 `research_allow_unresolved` 加载，`license_verified` 仍为 `false`。

| 指标 | 结果 |
|---|---|
| 输入 | 292 张 / 55 人（20—70 子集） |
| 解码 | 292/292 |
| 单人脸 | 290/292（99.3%） |
| 重建并取得 68 点 | 290/292 |
| 灰度图 | 22 张 |
| 检测置信度 | 均值 0.788、中位 0.801、P10 0.690、最低 0.507 |
| 点集最近邻偏差（对 FG-NET 68 点，按瞳距归一） | 均值 0.0815、中位 0.0806、P90 0.0928、最大 0.1098 |
| 匹配后 NME（经验映射，按瞳距归一） | 均值 0.0997、中位 0.0956、P90 0.1249、最大 0.1653 |

按十年统计：30—39、40—49、50—59、60—69 各段均 100% 单人脸；2 张失败都在 20—29 段。整批 CPU 推理约 8.6 秒（模型加载、哈希校验和报告写入另计）。

失败分类：

- `013A21.JPG`：扫描模糊、低对比；检测器原始最高候选分 0.315，低于 0.5 阈值。
- `067A23.JPG`：头部明显侧倾（约 45°）；原始最高候选分 0.368，同样低于阈值。

解释与限制：

- FG-NET 的 `.pts` 顺序不是 iBUG/3DDFA 的 68 点顺序（首段轮廓的起止点与 iBUG 下颌线不同）。因此主指标是不依赖点序的最近邻偏差；“匹配后 NME”使用的是一张由 290 张图最近邻分配多数投票得到的经验映射，稳定性 0.713、只覆盖 53 个 FG-NET 目标点，**不是官方对应规范**，不能当作独立基准。
- 0.08—0.10 瞳距的偏差只说明两套点大致落在同一批面部位置，不能证明身份保持、年尺度、纹理或 UV 接缝；没有做旋转 TTA，2 张失败样本也不代表检测器总体上限。
- 没有用这批样本拟合任何年龄方向、阈值或纹理参数，也没有做按身份的训练/测试划分。

复现：

```powershell
python tools/fgnet_pipeline_check.py `
  --detector-manifest data/models/yolov5n05-face/manifest.json `
  --reconstructor-manifest data/models/3ddfa-v2/manifest.json `
  --output-dir output/research/fgnet-pipeline-20261020 `
  --research-allow-unresolved
```

脚本要求输出目录不存在，逐图重算 SHA-256；哈希不符时该图标为 `hash_mismatch` 且不再继续推理，不会静默使用被替换的文件。
