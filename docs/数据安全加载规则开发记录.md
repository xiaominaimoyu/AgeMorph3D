## 1. 归档（v3 §5 第 4 条）

原有实现已经做到：不调用 `extractall()`、先完整预检再建输出目录、成员名走仓库统一路径规则（拒绝 `..`、绝对路径、盘符/冒号、反斜杠、控制字符、Windows 保留名和末尾点/空格）、ZIP 只接受普通文件/目录（链接、设备、FIFO、套接字一律 `SPECIAL_MEMBER`）、TAR 只接受基本普通文件/目录（链接、设备、PAX、GNU 长名、稀疏一律拒绝）、成员数/单成员/总解压量上限、ZIP 中央目录预算和 TAR 解压流计数。本次在此基础上补充：

| 规则 | 实现 | 拒绝码 |
|---|---|---|
| TAR `filter="data"` | 新函数 `tar_data_filter`：Python 缺少 `tarfile.data_filter` 时报 `TAR_DATA_FILTER_UNAVAILABLE`；每个 TAR 成员在预检和解压两个阶段都调用标准库 `tarfile.data_filter(member, <输出>/files)`；任何 `FilterError` 都是最终拒绝。成员仍由本工具逐个流式写成只读文件，从不交给 `extract/extractall` | `TAR_DATA_FILTER_REJECTED` |
| ZIP 本地头与中央目录一致 | 预检时逐个读取本地文件头，文件名、压缩方法、加密位必须与中央目录一致（防止中央目录写安全名、本地头藏 `../` 名） | `ZIP_LOCAL_HEADER_MISMATCH` |
| ZIP 条目不重叠 | 按偏移排序，每个条目的数据区不得与下一条目重叠，也不得伸进中央目录（防重叠条目型压缩炸弹） | `ZIP_ENTRY_OVERLAP` |
| ZIP 严格连续布局（2026-11-21 补强） | 文件开头就是第一个本地头（空包则只有结束记录）；条目之间、最后条目与中央目录之间不得有空隙；中央目录紧接结束记录；结束记录从后往前找、只认注释长度正好到文件尾的那个（这样的候选只能有 1 个，所选记录的注释里不得再有签名；成员数据里的签名不算），因此不允许尾随数据；`zipfile` 给出的中央目录起点和条目数必须与结束记录一致。拼接包、前置数据、尾随数据一律拒绝，不会只读出其中一个包 | `ZIP_PREFIX_UNSUPPORTED`、`ZIP_ENTRY_GAP`、`ZIP_DIRECTORY_NOT_ADJACENT`、`ZIP_END_AMBIGUOUS`、`ZIP_END_INVALID`、`ZIP_LAYOUT_UNSUPPORTED`、`ZIP_DIRECTORY_INVALID` |
| ZIP 压缩比 | 声明大小超过 1 MiB 的成员，解压后不得超过压缩大小的 200 倍 | `ZIP_COMPRESSION_RATIO_LIMIT` |
| 重名 | 重名判断从“只 casefold”改为“NFC 规范化 + casefold”，`café` 的组合/分解两种写法视为同名 | `DUPLICATE_MEMBER_PATH` |
| 失败成员不留半截文件（**待用户确认**） | 解压阶段某个成员失败（如 CRC 错误）时，删除本次为它写出的 `stage/*.part`；失败记录照常进入报告，其他成员照常处理。这一行为变化是否接受，尚待用户确认 | — |

以上新增检查都在创建输出目录之前完成（失败成员清理除外），被拒时工作区逐字节不变。ZIP 压缩比和 200 倍阈值是模块常量，没有加进计划的 `limits` 字段，所以已有计划 JSON 仍然有效。

**行为变化待用户确认：**原记录写“处理开始后的失败保留 stage 与报告”。当前实现会删除失败成员的半截 `.part`（报告和失败码保留），这是否接受尚待用户确认，不作为已定结论。另外 `feature_join.py` 把 `archive_preparation.py` 列入源码哈希清单，改动后旧的 P05 报告无法按原依赖哈希重放；`SCHEMA` 与报告格式没有变。

## 2. torch.load（v3 §5 第 1、5 条）

`safe_loading.torch_load_weights_only(root, pin, map_location="cpu")` 是唯一推荐的 checkpoint 加载入口：

1. 先校验 pin（相对路径、字节数、SHA-256）、后缀只允许 `.pt/.pth/.ckpt`、路径不能有符号链接/重解析点、大小上限默认 4 GiB；
2. 一次性读入内存再核对哈希，之后从这份内存字节加载，避免“核对后被换文件”；
3. 延迟导入 torch（模块顶层不导入，torch 仍是可选依赖）；torch 不存在报 `TORCH_UNAVAILABLE`，`torch.load` 没有 `weights_only` 参数报 `TORCH_WEIGHTS_ONLY_UNSUPPORTED`；
4. 始终 `weights_only=True`；加载报错一律 `TORCH_WEIGHTS_ONLY_REJECTED`，不会改成 `False` 重试。

## 3. 静态检查（启发式，不是证明）

`safe_loading.audit_source/audit_tree` 用 AST 检查仓库 Python 源码（跳过 `.git`、`.venv*`、`venv`、`node_modules`、`output`、`data` 等环境/数据/产物目录；另外唯一豁免 `backend/tests/test_safe_loading.py`，因为它以字符串形式存放检测器自己的正反例）。每个模块先解析 `import x as y` 与 `from x import y [as z]` 别名（`np` 默认视为 `numpy`），再按规范名判断：

| 规则 | 拒绝码 |
|---|---|
| `torch.load` / `torch.serialization.load`（含 `t.load`、`from torch import load`、`from torch.serialization import load`、`self.torch.load`）缺少字面量 `weights_only=True`，或带 `**kwargs` | `TORCH_LOAD_WITHOUT_WEIGHTS_ONLY` |
| `torch.jit.load`、`torch.hub.load`、`torch.hub.load_state_dict_from_url`（一律报告） | `TORCH_JIT_OR_HUB_LOAD` |
| `numpy.load` 的 `allow_pickle` 不是字面量 `False`（关键字或第三位置参数，如 `np.load(x, None, True)`），或带 `**kwargs` | `NUMPY_ALLOW_PICKLE` |
| `pickle/_pickle/cPickle/dill/joblib` 的 `load`、`loads`、`Unpickler(...)` | `PICKLE_LOAD` |
| 继承 `pickle.Unpickler` 的类 | `PICKLE_UNPICKLER` |
| `getattr(<torch/numpy/pickle/shutil/tarfile…>, 名称)`，名称不是字面量，或是 `load/loads/Unpickler/unpack_archive/extract/extractall/jit/hub` | `DYNAMIC_SENSITIVE_LOOKUP` |
| `from torch import *` 等敏感模块星号导入 | `STAR_IMPORT_FROM_SENSITIVE_MODULE` |
| 任意调用的 `trust_remote_code` 不是字面量 `False` | `TRUST_REMOTE_CODE` |
| 字典字面量里 `trust_remote_code`/`allow_pickle` 不是 `False`、`weights_only` 不是 `True`（覆盖 `**{'allow_pickle': True}` 这类写法） | `SENSITIVE_FLAG_IN_DICT` |
| `shutil.unpack_archive` 没有 `filter="data"` | `UNPACK_ARCHIVE_WITHOUT_DATA_FILTER` |
| 任何 `.extract(`/`.extractall(` 方法调用没有 `filter="data"`（含 `TarFile.extract`；ZIP 的 `extract` 没有该参数，也会被报告） | `EXTRACT_WITHOUT_DATA_FILTER` |
| 非文档字符串的 str/bytes 字面量含 `weights_only=False`、`trust_remote_code=True` 或 `allow_pickle=True`（用于发现“改写第三方源码”的补丁） | `SENSITIVE_FLAG_IN_STRING` |

`test_repository_has_no_new_unsafe_loads` 把全仓库结果按（文件、拒绝码、规范化代码片段）与已知清单逐条比对，**不是只比数量**：同一文件里把一处违规换成另一处写法不同的违规也会失败。残余盲区：文本完全相同的调用挪位置或复制到同一文件的同一片段不会被区分出“行号变化”（比对故意不含行号）。

这是启发式静态检查，用来拦住常见写法，**不能证明仓库没有不安全加载**。它看不到：经变量或函数参数传递的模块/函数对象（如 `f = torch.load` 后在别处调用只有赋值时不会报，调用时也无法还原）、`importlib.import_module`/`__import__` 动态导入、`exec`/`eval` 和运行时生成的代码、非 Python 文件（shell 脚本、Notebook）、第三方库内部的加载、由变量或拼接拼出的字符串补丁（如 `'weights_only=' + 'False'`）、`getattr(torch, 'serialization').load`（`getattr` 规则不把 `'serialization'` 当作敏感名，随后的 `.load` 也无法还原为 `torch.serialization.load`）、以及 JSON 风格写在字符串里的 `"weights_only": False`（字面量规则只匹配 `weights_only=False` 这种赋值写法）。以下加载器本次未纳入检查范围：`marshal`、`yaml.load` / `yaml.unsafe_load`、`pandas.read_pickle`、`shelve`、`cloudpickle`。例如 `tools/age_evaluator_probe.py` 用 `importlib` 直接导入本地固定的 MiVOLO 模型源码（等效于执行模型仓库代码，但走 `use_safetensors=True, local_files_only=True`），不在本检查范围内，这里如实列出供知悉。

## 4. 局限

- 第 3 节的静态检查是启发式，不是安全证明；盲区见上文。
- ZIP64、多磁盘、加密、自解压前缀、PAX/GNU 长名 TAR 仍不支持（原有策略），真实发行包超出时需要单独评审。
- 压缩比阈值 200 倍、1 MiB 起算是经验值，没有用真实数据集验证；文本或零填充较多的合法文件可能被拒，届时如实记录后再评估。
- ZIP 条目之间的少量空隙（例如数据描述符）允许存在，只拒绝重叠。
- `tarfile.data_filter` 需要 Python 3.11.4 及以上。`pyproject.toml` 写的是 `>=3.11,<3.12`，没有排除 3.11.0–3.11.3；本次没有改 pyproject/lock（改下限会动锁文件，留给用户决定），而是在缺少 `data_filter` 时显式拒绝为 `TAR_DATA_FILTER_UNAVAILABLE`，绝不跳过过滤；ZIP 不受影响。当前 3.11.16 / 3.11.18 均满足。
- torch 路径只用桩模块验证了参数和失败处理，没有用真实 torch 和真实 checkpoint 跑过。
