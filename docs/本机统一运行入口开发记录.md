# 本机统一运行入口

2026-10-31。对应 L01 的开发入口子项，B 主责。新增跨平台 Python 入口 [tools/local_run.py](../tools/local_run.py)，以及 Windows 包装 [tools/local-run.ps1](../tools/local-run.ps1)、[tools/local-run.cmd](../tools/local-run.cmd)。它只负责检查、状态、启动、停止和转交既有只读诊断；不安装依赖，不改系统配置，不改模型清单，不授予 ready 或年龄能力。

这不是生产静态前端，不是 L02 干净环境复现，也不是严格模型成功链或毕设整体完成。Vite 开发服务只作为当前本机联调入口，不能当作最终交付证明。

## 1. 行为

支持的服务命令保持原样：

- 后端：在 `backend/` 中执行 `python -B -m agemorph3d`，单进程，只绑定 `127.0.0.1:8000`。
- 前端：在 `frontend/` 中执行 Vite，`--host 127.0.0.1 --port 5173 --strictPort`。

Host/Origin 限制仍由现有服务实现。启动器不新增监听地址，也不把端口改成其他值。解释器默认是 `backend/.venv/Scripts/python.exe`（Linux 为 `backend/.venv/bin/python`），不会在缺失时改用系统 Python 充当服务进程。Node 依次使用环境变量 `AGEMORPH_NODE`、存在时的 `D:\JAVA run tools\node.exe`、否则 PATH 上的 `node`。

状态和日志只写项目内被忽略的 `output/local-run/`，也可用 `logs/` 下的显式目录。写到其他路径会被拒绝。停止前核对 pid、创建标记、可执行文件、命令行和本次所有者令牌；不一致就不发信号。不按端口查找并结束未知监听者。后端已启动但前端失败时，回滚本次拥有的后端进程。重复启动会被拒绝。Windows 后台进程使用隐藏窗口：`CREATE_NO_WINDOW`、`CREATE_NEW_PROCESS_GROUP` 和 `SW_HIDE`。

`diagnose` 只调用现有 `python -B -m agemorph3d.model_diagnostics`，该进程的工作目录仍是 `backend/`。文档里的相对清单路径按项目根目录解析成绝对路径后再传入，因此 `data\models\...` 不会被当成 `backend\data\...`。未配置清单时报告 `MANIFEST_NOT_CONFIGURED`；有清单时沿用该诊断的登记/完整性结论。诊断进程即使写出 `grants_service_readiness: true`，启动器自己的 `launcher_grants_ready` 仍为 false。启动器不调用 `/api/aging`。

退出码：0 表示检查通过、启动/停止完成，或诊断前置条件满足；1 表示诊断已完成但仍阻塞；2 表示缺解释器或依赖，且没有安装；3 表示端口被其他监听占用、重复启动或状态锁被占用；4 表示身份不一致，已拒绝发信号；5 表示启动失败并已回滚，或停止没有完成；6 表示路径、主机或不安全参数被拒绝。

## 2. 本机命令

在项目根目录执行。下面是用户 Windows 机器上的命令；路径含空格，不要去掉引号。

```powershell
Set-Location -LiteralPath 'D:\project file\AgeMorph3D'
$env:AGEMORPH_NODE = 'D:\JAVA run tools\node.exe'
.\tools\local-run.ps1 check
.\tools\local-run.ps1 diagnose `
  --detector-manifest 'data\models\yolov5n05-face\manifest.json' `
  --reconstructor-manifest 'data\models\3ddfa-v2\manifest.json'
.\tools\local-run.ps1 start
.\tools\local-run.ps1 status
Invoke-RestMethod 'http://127.0.0.1:8000/api/health' | ConvertTo-Json -Depth 6
try {
  Invoke-RestMethod 'http://127.0.0.1:8000/api/aging' -Method Post `
    -ContentType 'application/json' -Body '{"mesh_id":"abc","age":30}'
} catch {
  $_.Exception.Response.StatusCode.value__
  $_.ErrorDetails.Message
}
.\tools\local-run.ps1 stop
.\tools\local-run.ps1 start
.\tools\local-run.ps1 stop
```

cmd 包装是 `tools\local-run.cmd`，参数相同。也可以直接调用虚拟环境：

```powershell
& 'backend\.venv\Scripts\python.exe' -B 'tools\local_run.py' check
```

当前研究清单预期诊断退出码为 1，登记仍 unresolved，不能把它读成 ready。没有清单时是 `missing`/`MANIFEST_NOT_CONFIGURED`。健康检查里的模型状态来自服务自己的报告；HTTP 200 只说明进程可达。

原有两个终端的手动启动命令仍然有效，见 [backend/README.md](../backend/README.md)。

## 3. 这次实际验证

验证机器是 Linux 云端环境，不是用户的 Windows 本机。解释器为项目虚拟环境 Python 3.11.18，Node 为 v22.23.4。依赖是验证时单独执行的 `uv sync --locked` 和 `npm ci`，不是启动器安装的。仓库里没有真实模型，因此这次只能看到未配置清单的路径。

项目虚拟环境中的 Ruff 0.17.1 对 `tools/local_run.py` 和 `backend/tests/test_local_run.py` 检查与格式检查通过。`pytest -q tests/test_local_run.py` 为 15 项通过、1 项默认跳过。跳过项是固定 8000/5173 的真实循环，设置 `AGEMORPH_LOCAL_RUN_LIVE=1` 后 1 项通过。边界覆盖含空格路径、缺失解释器/导入、拒绝 pip/npm、他人占用端口、重复启动、前端失败回滚、篡改 pid 后拒绝停止、重启、状态锁，以及诊断不改清单。生产后端源码和前端源码未改，没有重跑已通过的 2956 项后端或 340 项前端。

随后直接执行启动器。`/api/health` 返回 200，检测/重建为 `missing`，四项能力均为 false。`POST /api/aging` 返回 503，`code` 为 `MODEL_NOT_READY`。前端 `http://127.0.0.1:5173/` 返回 200。停止结果是后端和前端均为 `sigterm`、`forced: false`，8000 与 5173 不再接受连接。`launcher_grants_ready` 与 `launcher_grants_aging` 均为 false。未配置清单时 `diagnose` 退出码 1，两个角色都是 `MANIFEST_NOT_CONFIGURED`，`grants_service_readiness` 为 false。

## 4. Windows 本机复核与两处修正

用户在 Windows 上用 Python 3.11.16、Node v24.14.1 跑了第 2 节的命令。`check` 通过，`problems` 为空。随后发现两处启动器缺陷，都已在同一分支修正。

相对路径的 `diagnose` 一律报 `MANIFEST_MISSING_OR_INVALID`。诊断子进程的工作目录是 `backend\`，文档中的 `data\models\...` 是相对项目根的路径，在那里找不到。改成绝对路径后结果符合预期：检测清单有效，`yolov5n-0.5-face.onnx` 哈希核对通过；重建清单有效，regressor、bfm、param_stats 都核对通过；唯一阻塞是两边清单的 `license_status` 仍为 unresolved，即 `LICENSE_REGISTRATION_UNRESOLVED`。这个阻塞必须保留，不能改成 ready。修正是把用户给出的相对路径先按项目根目录解析，再传给诊断进程。绝对路径保持绝对路径。

`start` 报 `START_FAILED`，尽管 uvicorn 日志已经写了 `Application startup complete` 且监听 `127.0.0.1:8000`，启动器随后结束了自己刚创建的进程。对照实验确认：`_windows_peb_text` 对整个环境块做一次 128 KiB 的 `ReadProcessMemory`，实际块只有 17,920 字节，读请求越过未映射页，返回 `ERROR_PARTIAL_COPY`（299），`observe()` 得到空身份。按页分块读取、在第一段读不完的地方停下后，同一进程能解析出 `AGEMORPH_LOCAL_RUN_OWNER` 和 `role=backend`。命令行读取改为同样的按页精确读取；长度不齐就视为身份不可用。环境块必须含有 UTF-16 的双 NUL 结尾才解析，截断内容不采用。身份仍然读不到时维持失败关闭：结束的是本次 `Popen` 创建的进程，不按端口寻找其他监听者。

那次失败之后，`status` 两边都是 absent，`stop` 为 `not_recorded`，8000 和 5173 都空闲，说明回滚本身成立。用户本地还有一份未跟踪的交接文档，与仓库副本只差 BOM，它挡住了 `git switch`；没有因此改代码。

Linux 上为这两处加了回归：相对 `data/models/...` 在诊断进程工作目录为 `backend/` 时仍能打开项目根下的清单；模拟“超过一页的读取返回空、页内短读停住”的环境块仍能取出所有者令牌；命令行跨页读满才接受，短读返回空。项目 Ruff 通过，`pytest -q backend/tests/test_local_run.py` 为 18 项通过、1 项真实循环默认跳过。修正后的 Windows 行为还要按下面命令再跑一遍，这次云端不能代替那次复测。

```powershell
Set-Location -LiteralPath 'D:\project file\AgeMorph3D'
$env:AGEMORPH_NODE = 'D:\JAVA run tools\node.exe'
.\tools\local-run.ps1 check
.\tools\local-run.ps1 diagnose `
  --detector-manifest 'data\models\yolov5n05-face\manifest.json' `
  --reconstructor-manifest 'data\models\3ddfa-v2\manifest.json'
.\tools\local-run.ps1 start
.\tools\local-run.ps1 status
Invoke-RestMethod 'http://127.0.0.1:8000/api/health' | ConvertTo-Json -Depth 6
.\tools\local-run.ps1 stop
```

诊断预期仍是退出码 1，且阻塞只剩 `LICENSE_REGISTRATION_UNRESOLVED`。`start` 后健康检查应能打开，`stop` 后再看 8000/5173。隐藏窗口，以及先手动占用 8000 时启动器不结束那个未知进程，仍请一并看一眼。
