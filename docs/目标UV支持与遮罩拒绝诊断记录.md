## 实现与统计语义

[uv_support_probe.py](../tools/uv_support_probe.py)读取每个目标自己的原始拟合、投影和ROI，使用原共同UV、原生有序三角形及原关键点坐标地址。原float32 UV先转float64再翻转v，与N4算术一致；不使用已量化的GLB UV作为光栅主输入。68×3关键点索引是坐标地址，存在不连续三元组，不能除3后当作顶点索引。

每个唯一UV texel保存原生face owner、a/b/c重心权重、目标投影XYZ及原始源canonical XYZ。源坐标采用同一个owner/权重在原始源顶点插值，再使用原源包围盒中心和统一比例；不按目标重新归一化。原生面序与GLB的a/c/b绕序分别处理，原源顶点/索引哈希同时核对。

区域由目标拟合关键点的XY框确定：眼36—41、眼42—47、鼻27—35、口48—67，分别向四边扩展该框宽/高的25%，使用左闭右开边界。它们是拟合框代理，可以重叠，不能相加作为互斥的人脸分区。分母包含框内所有唯一UV对应点，包括背面、出图、自遮挡及被mask拒绝的点；`support=sampled/requested`。UV外和UV歧义点没有唯一对应位置，另计全局分类。

重新计算正面、图内、连续max-Z可见性及所有正权双线性贡献像素的allowed判定，要求7类分类与保存图逐texel完全一致。对可见但被mask拒绝的点再分为：仅审查遮挡候选、仅其他不合格像素、两者混合。零权邻像素不触发拒绝。审查候选掩码不是真实遮挡标注；其他不合格同时包含保守不确定区、边界收缩及口部排除，不能进一步当作精确原因。

保存NPZ、atlas、分类PNG及coverage逐数组/像素一致；未知RGBA全零、alpha与coverage相符。输入先校验不可变字节再有界解码，禁用pickle；全部运算和向量写出前后重新核对112输入、运行环境及计划。漂移会使12条请求全部失效并移除本次向量，旧证据不覆盖。
