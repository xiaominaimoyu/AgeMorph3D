## 1. 使用入口与取得计划

从项目根目录查看 CLI：

```powershell
& 'backend/.venv/Scripts/python.exe' -m preprocessing.resource_acquisition --help
```

实际调用需要 `--root`、`--plan`、`--plan-sha256`、`--raw-dir` 与 `--work-dir`。相同计划与工作目录可重试；完整合成回归可直接复现，不需要数据或外网：

```powershell
cd backend
& '.venv/Scripts/python.exe' -m pytest tests/test_resource_acquisition.py -q
```

每个测试在临时目录创建极小用途/入口说明和固定字节内容，启动绑定 `127.0.0.1` 的 HTTP 服务，再生成带当前端口的计划。没有把不可用的固定端口、待填真实密码或未知哈希写成可直接运行的下载示例。

取得计划是与 D01 调查目录不同的严格契约；`docs/data-resources-v1.json` 含未知体积，不能直接被当成已准入下载输入。

| 字段 | 约束与意义 |
|---|---|
| `schema_id` | 固定 `agemorph3d-resource-acquisition-v1`，不接受多余/缺失字段或重复 JSON 键 |
| `plan_id/resource_id/resource_version` | 1—64 位有限 ASCII 标识，写入尝试收据；发行版本必须由实际来源材料确定 |
| `transport_scope` | `synthetic_loopback` 只允许字面量 loopback HTTP；`https_direct` 仅直接 HTTPS，后者本批未联网实测 |
| `purpose_evidence/entry_evidence` | 各含项目相对 `path`、准确 `bytes` 和小写 `sha256`；单份不超过16 MiB。核验的是记录文件字节，不判断记录是否授予权利或通过后端入口 |
| `max_total_bytes/reserve_bytes` | 必填整数预算，前者最多64 GiB，所有待取文件之和不得超出；读取当前盘余量作保守空间检查，不按未实测压缩率估算 |
| `files` | 1—32 个文件请求，每项含唯一 `file_id`、直接 `url`、原始目录内相对 `path`、准确正整数 `bytes` 和小写 `sha256`。32 是工程文件请求上限，不是压缩包内图像数量或统计样本量 |

计划文件最多128 KiB，必须给出原始 JSON 文件 SHA-256。用途/入口记录在任何网络请求前绑定，发布前再次检查，批次结束再检查。记录存在与哈希一致只称 `evidence_pins_verified`；`permission_assessment` 和 `backend_entry_assessment` 均为 `not_performed`。所有正式数据/训练/独立评价/服务/生产/G3标志始终为 false。

URL 不接受认证信息、查询串或片段，也不跟随重定向；禁用环境代理，不装载密码、Cookie 或认证处理器。因此当前工具适用于已有准确体积/哈希的静态直接文件，并未实现 Google Drive、Dropbox 密码、登录、签名链接或多段镜像适配。真实资源若只有这些取得方式，须另做具体适配与证据核验；不能仅凭有这个 CLI 把 D02—D04 勾为完成。

## 2. 下载、中断和发布行为

1. 预检计划、用途与入口记录、相对路径和空间。合成原始文件只写 `output/research/`；真实直接文件的目的范围为 `data/datasets/`，工作/收据始终位于 `output/research/`。原始与工作目录不得重叠；路径拒绝穿越、Windows保留名/非法字符、符号链接及reparse路径；文件名冲突按不区分大小写检查。
2. 独占工作目录的 `active.lock`，不接管已有锁。每文件使用独立 `.part` 和 `.state.json`，state绑定完整计划指纹及目的目录、当前偏移/前缀哈希与服务器强 ETag。前缀变化、计划变化、状态不完整或硬链接 partial 均拒绝续写。
3. 下载按至多64 KiB块读取，不把响应全部放入内存；没有 Content-Length 时仍受准确总字节上限约束。续传只接受 `206`、相同强 ETag、准确的 Content-Range 起止/总量；服务器忽略 Range 返回200不会追加或自动截断重来。缺少强 ETag 的中断文件保留，但不能按当前协议续传。
4. 网络中断和哈希等单文件失败保留 partial/state，并继续登记该计划的其余文件，完整请求分母不变。每次尝试生成新的 `attempt-<随机ID>.json`；旧失败不覆盖。读取到超量字节即拒绝，不写入超出目标大小的内容；重定向、非identity内容编码、重复关键头、错误长度/偏移/版本均保留明确错误码，响应错误正文不进入收据。
5. 完整候选必须符合准确字节数及 SHA-256，并在发布前整文件重读核对；先以硬链接原子创建新的目标名，成功后移除该次 partial 并设置只读文件属性。不替换已有原始文件。已存在且完整匹配、只读的文件可直接复核复用，不发网络请求；已存在的不同内容或可写文件保持原样并报错。

HTTP续传语义参照[HTTP标准 Range/If-Range/Content-Range](https://www.rfc-editor.org/rfc/rfc9110.html)，本工具采取上述更窄的直接文件协议。[Python 3.11 urllib 文档](https://docs.python.org/3.11/library/urllib.request.html)用于核对 opener、代理和超时行为。实现使用 HTTPResponse 的 `read1` 分块推进；socket操作默认10秒超时，批次默认120秒在连接/读取间检查已用时间。这是协作式期限，不宣称可强行中止系统DNS或持续发送头部的线程；真实长时/复杂云盘取得尚未验收。

只读是本机文件属性，尚未实现整个数据目录的权限隔离、解压安全性和逐图质量校验。若进程在 partial 与 state 的两次写入之间退出，下一次发现偏移/前缀不一致会拒绝续写；不会自行修补旧证据。已有锁或 `.tmp` 残留同样留待检查，可另建明确的新工作目录。工具也不提供自动重试、自动清理旧失败或多进程并发下载。
