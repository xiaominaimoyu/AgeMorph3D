# 近重复技术筛查记录

2026-10-23。本轮实现原始图像近重复候选筛查，并实际处理冻结N0的292张成人原图：哈希与解码全部通过，42,486个无序图像对、169,944个视图组合均完成比较，固定规则下候选为0。这个结果只表示本规则没有命中，不证明没有泄漏，也不签收独立评价或G3。

## 规则与实现

先冻结[技术协议](near-duplicate-v1.json)，再保存输入及源码/环境快照，最后运行[筛查CLI](../tools/near_duplicate_probe.py)。阈值8是预先选择、未经召回率校准的检索参数，未根据本批结果反调。协议与原N0分组保持不变，不修改原评价协议的pending记录。

每张图先在10MiB上限内读取一次字节快照，核验冻结大小/SHA-256，再由Pillow校验格式、单帧及1600万像素上限，执行EXIF方向校正并转RGB。像素指纹包含固定前缀、宽高、RGB标识和像素字节，区别于压缩文件指纹；不做ICC转换。随后对校正图和水平镜像各计算水平/垂直64位dHash：L灰度、LANCZOS缩放至9×8和8×9、严格大于比较、逐行高位先行。

每对图片比较四个视图组合。同一个组合必须同时满足Hamming水平≤8且垂直≤8；不能把不同视图的最小H/V拼成命中。保留全部命中视图，按无序图像对去重；32×32灰度MAE/255只作对应视图诊断，不再次过滤候选。相同压缩字节及相同尺寸绑定RGB像素另列证据，不直接推断同人或标签正确。

逐图失败保留在请求分母。声明或实际超限者不解码、不无界hash，明确标记未验证并使完整性失败；其他坏图即使字节hash正确，也会使筛查不完整。候选/组件分析后再对全部源图终检，漂移图及关联边剔除、组件与有效分母重算。元数据/源码漂移则拒绝发布报告，既有输出目录禁止覆盖。

组件只保存实际候选边。A—B、B—C命中不能推导A—C重复、同一身份或应合并分组。工具没有人脸识别或模型推理，也不自动生成缩略图、接触表或修改原始图像。
