## 0. 必须遵守的边界（第 1—6 条来自仓库和 v3 方案，第 7—8 条来自审核意见和用户情况）

1. **AI 不能替学生完成个人成果。** 说明书、开题报告、外文翻译的正文，以及真实的人工观察、教师意见、电子签名和验收，都必须由本人完成（`docs/毕业设计要求与交付清单.md` §1；`docs/验收矩阵.md` 第 55 行（表格最后一行）写“学生自己写正文”）。机器人只能提供提纲、事实索引、文献清单、数据表、统计结果、绘图规格和草稿素材。**论文和说明书里的图表由学生本人绘制**，因为任务书要求图表自行绘制（`docs/毕业设计要求与交付清单.md` 第 50 行）。
2. **Git 操作有限制。** 精确的文件清单确认之前不能做 Git 操作，不能全量暂存，不能强推，本地提交的授权也不等于推送授权（`RULES.md`“AI不得执行的操作”）。机器人的代码改动先放在 box 上的分支里，推送或开 PR 前要用户逐次批准。
3. **不能伪造许可或质量结论。** 不能把清单改成 verified 来让测试通过，不能把研究保留组改名为 test，不能用合成测试代替真实验收（`RULES.md`；`docs/后续任务清单.md` §9）。
4. **数据入口有门槛。** 按仓库规则，正式批量获取数据要先通过 R11/G1、R12/G2 的出口评审，并对 R13/R14 给出可行性结论；这一步之前，最多先做 32 条记录的工程小样（`docs/数据资源清单.md` §4；`docs/后续任务清单.md` §8 最后一段）。这条门槛和 v3 方案“现在就下载必需数据”有冲突，需要用户拍板，见第 6 节 Q4。
5. **执行环境有两台机器。** 模型、权重、FG-NET 数据和 `output/` 证据都在用户自己的 Windows 机器上（`D:\project file\AgeMorph3D`，这些目录被 git 忽略，见 `docs/2026-10-30_会话交接-AgeMorph3D-report.md` §7—8）。box 是 Linux，上面只有源码。**【推断】** 所以真实模型链路、实体摄像头、GPU 上的 SAM，都只能由用户在本机执行，机器人只能在 box 上做源码、合成测试和文档工作。
6. **AgeDB 只能放在用户本机。** v3 §2/§4 写明 AgeDB 只能“本机单一站点使用，不上云”。**【推断】** 因此 AgeDB 官方包不能下载到 box，Runner 和 Metric 都不能在 box 上处理它。所有要逐张处理 AgeDB 的步骤，都按第 3 节的“用户本机执行（LX）”任务来做：Forge 写脚本，用户在本机运行，**回传到 box 的只能是汇总数字和文件哈希**。逐图清单、文件名（AgeDB 文件名里含人名）、身份编号、图片和特征矩阵都不离开用户本机。
   box 上原有的 AgeDB 非官方转存 `/workspace/hf/agedb.parquet`（约 180 MB）和这条边界冲突，**已完成**：用户于 2026-11-15 21:01（UTC+8）在与 Atlas 的对话中明确同意删除，Atlas 随即删除并确认文件不存在；Sentinel 审核时下载的 /tmp/mh_meta.csv 也已确认不存在。删除前未记录 SHA-256。剩余事项：检查其他目录有无残留副本。
   v3 §4.5 原来写的是“授权后可以用转存比对元数据”，这一条**作废**。本规划所有 AgeDB 比对都只和 v3 §2-A 已记录的汇总数字比对，不再打开或使用任何转存。v3 §4.5 已经改好，Sentinel 复审时打开确认过。
7. **AgeDB 解压密码只留在用户手里。** 不发给任何机器人，不写进 box、仓库、日志、脚本参数或聊天记录。本机脚本设计成运行时由用户手动输入或自己解压，脚本本身不接收密码。

## 1. 项目现状

**项目定位。** 这是两人合作的本科毕设，A 负责算法和实验，B 负责系统和集成，两人姓名还没有和 A/B 对应上。学校的正式交付是 2027 年 6 月，内部完整交付目标是 2027-05-31（`README.md` 第 102 行；`docs/毕业设计要求与交付清单.md` §4）。系统流程是：照片或摄像头 → YOLO 检测 → 3DDFA_V2/BFM 重建 → 20—70 岁年龄形变，加上 SAM 纹理 → 导出 GLB/PNG。

**已完成的部分（实现和研究证据，不等于正式验收）**
- 前端：TypeScript + Vite + Three.js 工作台，包括演示模式、静态/年龄契约、导出、相机，以及独立的研究页面（`frontend/src/`、`frontend/research/`）。
- 后端：FastAPI 契约 v1.2，包括生命周期、准入/取消、GLB 缓存和 WS（`backend/src/agemorph3d/`、`docs/api.md`）。已用真实 CPU 模型从成年人像生成静态 GLB，Chrome/Edge 往返测试通过（`README.md` 第 79 行）。
- 研究链：真实 SAM → 目标 UV 研究闭环，K2 年龄形状基线做了 942 条请求、100 份 GLB 的复核（`docs/年龄形状实际网格与渲染复核.md`）。K4 离线评审工具已有 320 项待填表，AI 观察结果是 160 项有问题、160 项无法判断。
- 数据和训练的工程前置：`preprocessing/` 下 D06/P01—P06 的工具都已完成合成验证，`training/preflight.py` 和 `baseline-draft-v1.json` 是 T01 的草案。
- 交付侧：L01 统一运行入口 `tools/local_run.py`、`--production` 模式（PR #1/#2），L02 复现准备 `tools/repro_check.py`（PR #3），L03 行数统计 `tools/code_stats.py` 和 B 的章节提纲（PR #4）。2026-11-01 两份模型清单按所有者决定登记为“学术非商业、不转分发”（PR #5）。
- 测试回归来自两个不同批次的保存证据，不能合并引用：K2 批（`README.md` 第 11 行）后端完整回归 2956 项通过；K4 批（第 13 行）后端 2926 项、前端 340 项通过。

**还没完成的部分（`docs/验收矩阵.md`）**
- G1 严格真实静态链路没有通过。G2 正式实时链路没有通过。G3 年龄形状仍是 `static_fallback`、`years_calibrated=false`；年龄纹理的重点 32 帧仍是 NO_FACE，真实人工评审没做。`/api/aging` 仍返回 `503 MODEL_NOT_READY`。
