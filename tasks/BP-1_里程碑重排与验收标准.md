## 1. 重排规则（本文自己遵守的口径）

1. **一项一个归属阶段**：每个编号只归入一个阶段，即其清单“交付物与验收”列可以签收的阶段。任务可以更早开始或分段推进，前段只写成“检查点”（不签收），不计入归属，也不算完成。
2. **依赖顺序**：清单“依赖”列里的每个前置编号，必须在**更早的阶段**签收，或在**同一阶段且排在前面**（§4 各阶段“本阶段任务”的列出顺序即签收顺序）。唯一例外是 R11 ← R08 的部分依赖，见 §7.3，已登记。附录 A 第 3 部分用脚本逐条检查。
3. **不压缩验收**：每项任务的出口 = 清单该行“交付物与验收”原文 + 矩阵对应行的“剩余可验证出口”。§4 出口表里的条款摘录是**要点，非穷尽，以清单原文为准**；摘录没写到的条款同样必须满足。本文只增加可检验性（证据文件、签收人），不删、不放宽任何条款；没有依据的数值阈值保持“待制定”，不从已看结果倒推（矩阵第 41 行）。
4. **不伪造**：不把清单改成 verified 来过测试，不把研究保留组改名 test，不用合成测试代替真实验收（规划 v2 §0.3）。AI 不代写正文、不代填人工观察/签名（交付清单 §1、矩阵第 55 行）。
5. **日期**：学校日期只取交付清单 §4；内部原定日期只取总规划 §4 和规划 v2；新日期一律标【建议/待确认】。
6. **证据位置三类**：box 上 `/workspace/AgeMorph3D_tasks/<任务ID>_*.md`（规划 v2 §3 约定）；用户本机 `D:\project file\AgeMorph3D\output\…`（被 git 忽略，具体文件名由 BP-3/RN-4/FG-8 定义）；仓库 `docs/…`（只能由用户或经 U-9 批准后更新）。标【建议路径】的是本文提议的新文件名，Atlas 可改名，但须一处登记。
7. **AgeDB 只在用户本机**：所有逐图处理走 LX 任务组，回传 box 的只有 `summary.json`（汇总数字 + SHA-256）；密码不进 box、仓库、日志和聊天（规划 v2 §0.6—0.7）。
8. **签收与审核分开**：**签收**只由仓库主责（A/B）或用户本人做，矩阵对应行由用户更新证据与检查范围（矩阵第 59 行“须更新对应证据与检查范围，而非仅更新测试总数”）。**Sentinel 只是审核方**：审核 PASS 是签收的前置条件，但 Sentinel 不签收。§4 每张出口表都把“签收”和“审核”分成两列。
